# 审批与同住人申请历史记录可见性需求规格

## 执行摘要

用户反馈：“审批代办页面完成审批后，就看不到记录了”，并明确提出“用户审批待办后的记录需要能够查看。同样的，同住人的申请通过记录，也应该要能够查看”。本批在现有 Web 用户端补齐**审批人视角**的历史记录，同时保留申请人现有记录能力。

- 功能需求 5 条（REQ-FUNC-385～389）；非功能需求 0 条。
- INFERRED 0 条；0 ÷ (5 + 0) = 0%，低于画像上限 20%。
- 编号核对：本批之外全仓最大编号为 REQ-FUNC-384、REQ-NFUNC-084、C-401；本批约束从 C-402 起。
- 优先级默认规则：用户明确提出的能力及防止其既有能力回退的要求为 Must Have，其余为 Should Have。本批 Must Have 5 条，Should Have 0 条。
- 本轮流程边界：只完成需求规格与用户故事；用户确认前不进入架构、开发、测试或部署。

## 非功能需求

本批无新增非功能需求。历史记录的权限隔离、只读性和既有规则不变作为下述约束验收。

## 约束

- **C-402**：已处理记录的收录依据是当前用户实际发生的通过/拒绝动作，而不是“曾被指定为审批人”或“整单已由他人处理”。来源：`backend/apps/approval/services.py:183-188`；用户原文“用户审批待办后的记录”。
- **C-403**：查看历史记录是只读操作，不得新增或修改审批动作，不得改变整单状态、当前步骤、业务生效结果、撤回结果或同住人身份结果。来源：现有审批与同住人处理规则 `backend/apps/approval/services.py:155-245`、`backend/apps/residency/views.py:521-559`。
- **C-404**：通用审批过程详情继续沿用现有可见范围：发起人、该实例流程中的审批人及有权限的管理员可查看；其他用户不可见。已处理列表的“本人实际处理过”口径不得反向收窄既有时间线权限。来源：`backend/apps/approval/services.py:279-305`。
- **C-405**：同住人“已通过记录”按当前有效产权归属隔离；产权业主不得查看其无当前产权之专有部分的申请记录。离任后的历史可见性见 Q-AH-03。来源：现有审批权限 `backend/apps/residency/views.py:509-512,529-530`。
