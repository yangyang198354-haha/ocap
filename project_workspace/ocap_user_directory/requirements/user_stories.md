# 注册用户目录信息展示 用户故事（增量）

## 执行摘要

- 覆盖 REQ-FUNC-123 ~ 128 共 6 条 Must Have 功能需求与 REQ-NFUNC-019/020。
- 用户故事 5 个（US-132 ~ 136），全部 Must Have，故事点合计 16 [ESTIMATE]。
- 验收标准 18 组，全部为 Given / When / Then。
- 角色：仅管理员可见与使用；注册用户/游客不接触该页面。
- 编号续接全局最大 US-131，本增量从 US-132 起。

## 用户故事

### US-132: 查看注册用户的最高身份与专有部分认证状态

- 故事：As a 管理员, I want to 在注册用户列表看到每位用户的最高身份和是否已认证专有部分, so that 我能快速区分游客、产权业主、同住人与业委会成员并判断其认证情况
- 关联需求：REQ-FUNC-123、REQ-FUNC-124；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-132-01：Given 列表中有用户 A（户主，1 套有效认证）、用户 B（无任何认证）、用户 C（业委会委员且为户主）、用户 D（同住人，1 套有效认证） / When 管理员打开“账号”页的注册用户列表 / Then A 的身份显示“户主”、认证显示“已认证（1 套）”；B 的身份显示“游客”、认证显示“未认证”；C 的身份显示“业委会委员”；D 的身份显示“同住人”、认证显示“已认证（1 套）”
- AC-132-02：Given 某用户同时是业委会主任与户主 / When 列表加载 / Then 该用户身份只显示“主任”，不同时显示“户主”
- AC-132-03：Given 某用户同时是业委会副主任与产权业主 / When 列表加载 / Then 该用户身份只显示“副主任”
- AC-132-04：Given 某用户只有已过期的业委会席位，同时是产权业主 / When 列表加载 / Then 该用户身份显示“产权业主”，不显示任何业委会职务
- AC-132-05：Given 某用户在两套专有部分有有效认证（一套户主、一套产权业主） / When 列表加载 / Then 认证显示“已认证（2 套）”，身份显示“户主”
- AC-132-06：Given 非管理员已登录用户 / When 其请求注册用户列表数据 / Then 请求被拒绝，并提示无管理员权限，不返回任何用户信息

### US-133: 查看产权业主的清册实名

- 故事：As a 管理员, I want to 在注册用户列表看到产权业主在清册中登记的实名, so that 我能核对账号背后的真实产权人
- 关联需求：REQ-FUNC-125；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-133-01：Given 用户 A 的手机号在已认证房屋的清册中匹配到业主“张三” / When 列表加载 / Then A 的实名列显示“张三”
- AC-133-02：Given 用户 B 在两套已认证房屋的清册姓名分别为“张三”和“李四” / When 列表加载 / Then B 的实名列显示“张三、李四”，两个姓名各出现一次
- AC-133-03：Given 用户 C 在两套已认证房屋的清册姓名都为“张三” / When 列表加载 / Then C 的实名列只显示“张三”，不重复显示
- AC-133-04：Given 用户 D 只是游客或同住人，或手机号为空，或手机号未在任何已认证房屋的清册中匹配到业主 / When 列表加载 / Then D 的实名列显示“—”，不展示任何姓名
- AC-133-05：Given 用户 E 的认证已被撤销，但清册中仍保留其手机号 / When 列表加载 / Then E 的实名列显示“—”，不按已撤销的认证展示姓名

### US-134: 查看注册用户的上一次登录时间

- 故事：As a 管理员, I want to 在注册用户列表看到每位用户上一次成功登录的时间, so that 我能判断账号是否仍在使用
- 关联需求：REQ-FUNC-126；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-134-01：Given 用户 A 最近一次成功登录发生在 2026-11-10 09:05（Asia/Shanghai） / When 列表加载 / Then A 的上次登录时间显示“2026-11-10 09:05”
- AC-134-02：Given 用户 B 从未成功登录 / When 列表加载 / Then B 的上次登录时间显示“从未登录”，不显示空白或错误日期
- AC-134-03：Given 用户 C 先于 10:00 通过微信登录，后于 11:30 通过手机号验证码登录 / When 列表加载 / Then C 的上次登录时间显示“11:30”对应的日期时间，而不是 10:00
- AC-134-04：Given 用户 D 最近一次登录发生在昨天 23:50（Asia/Shanghai） / When 列表加载 / Then 显示“YYYY-MM-DD 23:50”格式的绝对时间，不显示“昨天”或相对时间

### US-135: 保留现有列表与搜索并支持实名搜索

- 故事：As a 管理员, I want to 在保留现有账号、手机号、昵称、状态列与搜索方式的同时按实名搜索用户, so that 我能用业主姓名直接找到账号
- 关联需求：REQ-FUNC-127、REQ-NFUNC-019；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-135-01：Given 管理员打开注册用户列表 / When 列表加载完成 / Then 账号、手机号、昵称、状态四列仍然存在，且手机号按现有规则脱敏显示（如“138****0001”），不显示完整号码
- AC-135-02：Given 用户 A 的清册实名为“张三” / When 管理员在搜索框输入“张三” / Then 结果包含用户 A
- AC-135-03：Given 管理员按账号、昵称、完整手机号或手机号后 4 位搜索 / When 提交搜索 / Then 返回结果与本次改动前一致，原有搜索行为不变
- AC-135-04：Given 管理员输入一个不存在的实名 / When 提交搜索 / Then 返回空列表，页面不报错且分页控件正常显示
- AC-135-05：Given 管理员打开列表 / When 查看分页 / Then 默认每页数量与现有注册用户列表一致，新增列不改变分页大小与按 id 升序的排序

### US-136: 撤销认证后目录信息保持一致

- 故事：As a 管理员, I want to 在撤销产权认证后，列表中的身份、认证数量与实名立即反映当前有效状态, so that 我不会把已撤销的用户误认为产权业主
- 关联需求：REQ-FUNC-128；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-136-01：Given 用户 A 只有一套房屋的产权业主认证，管理员撤销该认证 / When 再次打开注册用户列表 / Then A 的身份显示“游客”、认证显示“未认证”、实名显示“—”
- AC-136-02：Given 用户 B 在两套房屋均为产权业主，管理员撤销其中一套 / When 列表加载 / Then B 的认证显示“已认证（1 套）”，实名只保留仍有效那套房屋的清册姓名
- AC-136-03：Given 用户 C 的户主认证被撤销但同住人身份仍有效 / When 列表加载 / Then C 的身份显示“同住人”，认证显示“已认证（1 套）”，实名显示“—”
- AC-136-04：Given 用户 D 的业委会席位到期且没有其他身份 / When 列表加载 / Then D 的身份显示“游客”、认证显示“未认证”，不残留业委会职务
