# 用户故事：身份文案、列表对齐与申诉审核表格化

## 用户故事

### US-282: 汇总身份看得清，身份名称写全
- 故事：As a 已认证业主/业委会成员, I want to 在“我的身份与房屋”页一眼看清自己的汇总身份并看到完整职务名称, so that 不用眯眼猜测“主任”是哪个组织的主任
- 关联需求：REQ-FUNC-276、REQ-FUNC-277、C-96；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-282-01：Given 用户已登录并打开“我的身份与房屋” / When 页面加载完成 / Then “汇总身份”文案字号 ≥ 16px，身份值以不小于大号标签的尺寸显示，视觉上明显大于现有的小标签
- AC-282-02：Given 用户身份为业委会主任 / When 查看汇总身份 / Then 显示“业委会主任”；身份为副主任、委员、业主代表时分别显示“业委会副主任”“业委会委员”“业主代表”；产权业主、同住人、游客分别显示“产权业主”“同住人”“游客”
- AC-282-03：Given 汇总身份与“真实姓名”在同一行 / When 视口宽度为 1280px / Then 两者基线对齐、互不遮挡；在 375px 宽度下允许换行，但文字不被截断、不溢出卡片
- AC-282-04：Given 后端返回未知身份 code / When 页面渲染 / Then 原样显示该 code，页面不报错
- AC-282-05：Given 同一用户的房屋列表 / When 查看每套房屋的角色标签 / Then 仍显示“户主 / 产权业主 / 同住人”，不被职务全称替换
- AC-282-06：Given 某用户为业委会委员 / When 该身份出现在决议发起人、审批人、管理端用户目录等其他展示位置 / Then 同样显示“业委会委员”；“业委会席位”页的“职位”列仍显示“委员”（D-01）
- AC-282-07：Given 迁移前存在身份快照为“主任 / 副主任 / 委员 / 业主代表”的历史决议与收入表 / When 执行身份文案迁移 / Then 这些记录改显示“业委会主任 / 业委会副主任 / 业委会委员 / 业主代表”，金额、票数、发起人、时间、状态等其余字段与关联不变；重复执行不再产生变化（D-05）

### US-283: 公开决议按“进行中 / 已结束”分区
- 故事：As a 业主, I want to 在公开决议页把进行中的决议和已结束的决议分开看, so that 我能先关注还需要表决的事项，不被大量历史决议淹没
- 关联需求：REQ-FUNC-278、REQ-FUNC-280、C-99；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-283-01：Given 公开决议当前页同时有进行中与已结束决议 / When 页面加载完成 / Then 页面依次出现“进行中（n）”与“已结束（n）”两个分区标题，各自只包含对应状态的卡片，标题条数等于该分区在当前页的卡片数
- AC-283-02：Given 当前页全部为已结束决议 / When 页面渲染 / Then 不出现“进行中”空分区标题，直接显示“已结束（n）”分区
- AC-283-03：Given 当前页没有任何决议 / When 页面渲染 / Then 显示“暂无决议”，不显示任何分区标题
- AC-283-04：Given 用户切换到“我发起的”或“待我表决” / When 列表加载 / Then 这两个分区保持原有单列表展示，不出现进行中/已结束分组
- AC-283-05：Given 公开决议第 2 页 / When 切换到第 2 页 / Then 分区标题条数按第 2 页数据重新计算，底部总数仍为筛选后的全部决议数
- AC-283-06：Given 分区标题 / When 用户点击标题文字 / Then 不触发任何卡片跳转；点击卡片标题仍进入决议详情

### US-284: 进行中决议排在公开决议前面
- 故事：As a 业主, I want to 公开决议列表把进行中的决议排在前面, so that 进行中的表决不会因为分页被排到后面几页
- 关联需求：REQ-FUNC-279、REQ-FUNC-280、C-99；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-284-01：Given 公开决议存在进行中与已结束记录 / When 请求公开决议第 1 页 / Then 所有进行中记录先于已结束记录出现；同为进行中或同为已结束的记录按发起时间倒序
- AC-284-02：Given 公开决议有 25 条进行中、60 条已结束 / When 逐页取完所有页 / Then 前两页全部为进行中记录，第 3 页起才出现已结束记录，且所有记录不重复、不遗漏
- AC-284-03：Given 某进行中决议未到表决截止 / When 列表刷新 / Then 它仍处于“进行中”分区且可见范围与变更前一致
- AC-284-04：Given “我发起的”与“待我表决”列表 / When 加载 / Then 排序与变更前一致
- AC-284-05：Given 公开决议数据中只有已结束记录 / When 加载 / Then 列表仍按发起时间倒序展示

### US-285: 业主清册的筛选控件与表格列对齐
- 故事：As a 管理员, I want to 清册的每个筛选控件正对它所筛选的列, so that 我不用反复对照就能知道哪个框筛哪一列
- 关联需求：REQ-FUNC-281、REQ-FUNC-282、REQ-NFUNC-056；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-285-01：Given 视口宽度 ≥ 1280px / When 打开业主清册 / Then 专有部分搜索、楼栋、单元、户号、类型、业主姓名、业主电话、重置依次对齐“专有部分 / 楼栋 / 单元 / 房号 / 类型 / 业主（合并）/ 操作”列，左边界误差 ≤ 4px
- AC-285-02：Given 清册表格 / When 渲染 / Then 列宽为专有部分 180、楼栋 90、单元 90、楼层 90、房号 100、类型 110、面积 110、业主 240、操作 150；面积列没有筛选控件，但筛选区保留对应空位
- AC-285-03：Given 视口宽度 1024px / When 打开业主清册 / Then 筛选区与表格作为整体横向滚动，控件不压缩、不换行、不与相邻列重叠
- AC-285-04：Given 任一状态下 / When 查看操作列 / Then “编辑”“删除”两个按钮在同一行显示，不换行
- AC-285-05：Given 清册筛选任意列 / When 输入或选择并触发查询 / Then 请求参数与变更前一致，结果集不变（仅布局变化）
- AC-285-06：Given 浏览器缩放 125% / When 打开业主清册 / Then 筛选控件仍与对应列左边界对齐（容差 ≤ 4px），无横向溢出到卡片外
- AC-285-07：Given 清册表头 / When 查看任意可排序列 / Then 筛选控件位于表头上方的独立区域，不与列名、排序箭头混排；表头高度与变更前一致（D-06）

### US-286: 业主清册可以选每页显示多少条
- 故事：As a 管理员, I want to 一次多看一些清册记录, so that 核对楼栋数据时不用频繁翻页
- 关联需求：REQ-FUNC-283、REQ-FUNC-283、C-97；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-286-01：Given 业主清册已加载 / When 查看分页区 / Then 可选择 20 / 50 / 100 条每页，默认 20
- AC-286-02：Given 当前在第 3 页 / When 把每页条数从 20 改为 50 / Then 自动回到第 1 页，按 50 条重新加载，总数与页数计算正确
- AC-286-03：Given 已填写楼栋、类型、关键词并设置排序 / When 切换每页条数或翻页 / Then 筛选条件与排序保持不变，仅分页参数变化
- AC-286-04：Given 有 230 条记录、每页 50 条 / When 翻到最后一页 / Then 显示 30 条，且“下一页”不可用
- AC-286-05：Given 每页条数选择 / When 刷新页面 / Then 恢复默认 20 条（本批不做跨会话记忆）

### US-287: 产权申诉审核改为信息完整的表格
- 故事：As a 管理员, I want to 在表格里看到申诉人的头像、昵称、手机号等关键信息并分页处理, so that 我不用在一堆挤在左侧的文字里找人找房
- 关联需求：REQ-FUNC-285、REQ-FUNC-286、REQ-NFUNC-056、C-98；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-287-01：Given 打开产权申诉审核 / When 页面加载完成 / Then 申诉以表格呈现，表头为“申诉编码 / 申请人 / 联系电话 / 产权人姓名 / 专有部分 / 申诉时间 / 状态 / 证明材料 / 拒绝原因 / 操作”，表格占满内容区
- AC-287-02：Given 某申诉人已设置头像 / When 查看该行“申请人”列 / Then 显示头像、昵称与账号；未设置头像时显示内置默认头像，未设置昵称时显示“未设置”
- AC-287-03：Given 申诉人已绑定手机号 / When 查看“联系电话”列 / Then 显示脱敏号码；未绑定时显示“未绑定”，且状态为 `PENDING` 的行显示“通过后清册只写姓名、不写联系电话”
- AC-287-04：Given 历史申诉没有产权人姓名 / When 查看该行 / Then 显示“未提供”，表格不错行
- AC-287-05：Given 某申诉附带 5 份证明材料 / When 查看“证明材料”列 / Then 最多显示 3 个缩略图与“+2”，行高不超过 140px；点击缩略图仍可预览并可上一份/下一份切换
- AC-287-06：Given 申诉状态筛选为“待审核” / When 表格加载 / Then 只有 `PENDING` 行显示“通过 / 拒绝”按钮；切换状态筛选后回到第 1 页
- AC-287-07：Given 申诉共 130 条 / When 选择每页 50 条 / Then 分页区显示 3 页，第 3 页 30 条；翻页时状态筛选保持
- AC-287-08：Given 管理员点击“通过”或输入原因后“拒绝” / When 操作成功 / Then 列表按当前筛选刷新，行为与变更前一致，不新增任何权限
- AC-287-09：Given 非管理员 / When 请求申诉列表接口 / Then 仍被拒绝（权限行为不变）

### US-288: 房屋关系的筛选与列对齐，并可按专有部分/户号查找
- 故事：As a 管理员, I want to 在房屋关系页按专有部分标识或户号快速定位, so that 业主报出房号时我能直接找到对应的人和关系
- 关联需求：REQ-FUNC-284、REQ-FUNC-282（列宽口径）、REQ-NFUNC-056；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-288-01：Given 视口宽度 ≥ 1280px / When 打开用户房屋关系 / Then 身份、楼栋、单元、楼层、关键词、专有部分标识/户号各控件分别对齐“身份 / 专有部分（合并）/ 用户 / 专有部分 / 操作”对应列，左边界误差 ≤ 4px；列宽为用户 160、专有部分 200、身份 120、认证时间 180、操作 140
- AC-288-02：Given “专有部分标识 / 户号”输入框 / When 输入 `1栋1单元1层101号` / Then 返回该专有部分的房屋关系记录；输入户号 `101` 也能命中同一记录
- AC-288-03：Given 同时选择楼栋 `1栋`、身份 `产权业主` 并输入户号 `101` / When 查询 / Then 返回同时满足三个条件的记录（条件取交集）
- AC-288-04：Given 输入不存在的标识 / When 查询 / Then 显示“暂无匹配记录”，不报错
- AC-288-05：Given 已设置筛选 / When 点击“重置”或清空该输入框 / Then 清空专有部分标识/户号条件并回到第 1 页，其余筛选行为与变更前一致
- AC-288-06：Given 视口宽度 1024px / When 打开该页 / Then 筛选区与表格整体横向滚动，控件不压缩重叠
- AC-288-07：Given 房屋关系共 130 条 / When 选择每页 50 条 / Then 回到第 1 页并按 50 条加载，分页显示 3 页；切换条数后楼栋、单元、楼层、身份与专有部分标识/户号条件保持不变（D-03）
- AC-288-08：Given 原关键词框 / When 输入 `1栋1单元1层101号` / Then 该框不再按专有部分匹配（提示改为“姓名 / 手机号（后 4 位起）”），专有部分只由新控件命中（D-07）

### US-289: 业委会席位的筛选控件与表格列对齐
- 故事：As a 管理员, I want to 席位页的职位、楼栋、单元筛选正对相应列, so that 查某个楼栋的代表时视线不用来回跳
- 关联需求：REQ-FUNC-287、REQ-NFUNC-056、C-100；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-289-01：Given 视口宽度 ≥ 1280px / When 打开业委会席位 / Then 职位下拉对齐“职位”列；楼栋与单元两个下拉并排在“专有部分坐落”列内，各占该列一半宽度；左边界误差 ≤ 4px
- AC-289-02：Given 席位表格 / When 渲染 / Then 列宽为昵称 110、姓名 80、联系电话 110、专有部分坐落 200、专有部分类型 100、职位 90、状态 120、任期开始 95、任期结束 95、操作 220
- AC-289-03：Given 选择职位为“委员” / When 查询 / Then 结果与变更前一致（筛选参数不变），仅布局变化
- AC-289-04：Given 选择楼栋后 / When 单元下拉加载选项 / Then 仅显示该楼栋下的单元，行为与变更前一致
- AC-289-05：Given 视口宽度 1100px / When 打开席位页 / Then 筛选区与表格整体横向滚动，控件不与相邻列重叠
- AC-289-06：Given 席位列表已按职位/楼栋/单元筛选 / When 选择每页 50 条 / Then 回到第 1 页并按 50 条加载，筛选条件与“资格失效 / 已结束”折叠区数据口径保持不变（D-03）
- AC-289-07：Given 展开“资格失效 / 已结束”折叠区 / When 查看条数 / Then 仍最多返回 50 条且无分页与每页条数控件（D-08）

### US-290: 席位页控件错位与挤压修复
- 故事：As a 管理员, I want to 席位页的标题、提示、筛选与表格左边界一致且操作按钮不被挤掉, so that 我能正常变更职位或撤销席位
- 关联需求：REQ-FUNC-288、REQ-NFUNC-056、C-100；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-290-01：Given 打开业委会席位 / When 页面渲染 / Then 标题、人数与任期说明、提示文案、“修改人数与任期”按钮与筛选区左边界一致，不再挤在左侧窄列
- AC-290-02：Given 某在任席位行 / When 查看操作列 / Then “变更为”下拉（110px）与“变更职位”“撤销”按钮在同一行完整显示，不换行、不被截断
- AC-290-03：Given 表格数据较少 / When 渲染 / Then 各列保持预设宽度，不因内容少而塌陷错位
- AC-290-04：Given 表格内容超出可用宽度 / When 浏览 / Then 表格自身横向滚动，页面 1280px 下不出现整页横向滚动条
- AC-290-05：Given 展开“资格失效 / 已结束”折叠区 / When 查看 / Then 折叠区与主表左边界对齐，表头与行不错位
- AC-290-06：Given 任一席位操作（变更职位、撤销、赋予席位、保存配置） / When 执行 / Then 结果与变更前一致，权限与业务规则不变

## 验收覆盖说明

- Must Have 故事 9 条（US-282 ~ US-290），Should Have 0 条。
- 前端可自动化覆盖：US-282（文案映射与字号类名）、US-283/284（分组与排序请求参数、分区渲染）、US-285/288/289（列宽 token 与筛选控件存在性）、US-286（分页参数与回第 1 页）。
- 需人工/浏览器验收：逐列像素级对齐（容差 ≤ 4px）、125% 缩放、375px 身份页、缩略图行高与预览、席位页操作列换行。
- 后端自动化覆盖：US-282（历史身份文案迁移：迁移前后字段 diff 仅身份文案、重复执行幂等）、US-284（public 排序）、US-287（`avatar_url` 只读字段与权限）、US-288（专有部分标识/户号过滤交集）。
