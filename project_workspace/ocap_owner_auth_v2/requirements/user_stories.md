## 用户故事

### US-193: 选房第一级只有三大类
- 故事：As a 登录用户, I want to 在"我的房屋"选房第一级只看到 1~10 栋、地下车位、商铺三类, so that 选择非常整洁（"住宅的10个楼栋，地下车位，商铺 三大类就可以了"）
- 关联需求：REQ-FUNC-185、REQ-FUNC-186；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-193-01：Given 清册有楼栋 1~10、"地下车位"与商铺记录 / When 用户（Web 与小程序各验一次）打开选房第一级 / Then 选项依次为 1、2、……、10、地下车位、商铺（共 12 项），两端逐项相同，没有门牌型楼栋（如"建设南路142号"）作为并列入口
- AC-193-02：Given 1 栋内原有类型为商铺的记录（含 id=4347） / When 用户选择 "1" 栋并逐级选到楼层与户号 / Then 选项中不出现任何类型为商铺的记录；选择 "商铺" 后能找到 id=4347 对应的商铺
- AC-193-03（边界）：Given 类型为空或"其他"的记录位于 1~10 栋内 / When 用户选择该栋 / Then 这些记录仍在原栋内，不被归入"商铺"（C-60）
- AC-193-04（边界，Q-OA-04=A）：Given 清册新导入一个第四种楼栋 "配套用房"（非商铺类型） / When 用户打开第一级 / Then 该楼栋以原名出现在"商铺"之后，不丢失、不被合并进三大类
- AC-193-05（边界）：Given 清册中没有任何商铺记录 / When 用户打开第一级 / Then 不出现"商铺"选项，其余顺序不变，页面无报错

### US-194: 逐级选到某个商铺并认证
- 故事：As a 登录用户, I want to 选"商铺"后依次选原楼栋/门牌、楼层、户号, so that 我能唯一定位自己的商铺并发起认证（包括只有门牌号、没有单元信息的商铺）
- 关联需求：REQ-FUNC-187；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-194-01：Given 用户选择"商铺" / When 查看第二级 / Then 选项为商铺的原楼栋/门牌（含 1、2、5、6、9、10 栋与 27 个门牌型楼栋名，共约 33 项，以授权核对的实际数为准），数字楼栋按自然顺序在前（2 在 10 之前）
- AC-194-02：Given 用户选了门牌型楼栋"建设南路142号"（无单元、无楼层信息） / When 继续选择 / Then 空层级自动跳过，直接给出该门牌下的商铺户号选项，选定后进入姓名输入与认证（US-200）
- AC-194-03：Given 同一原楼栋下有多个商铺且楼层、户号不同 / When 用户逐级选择 / Then 每个商铺恰有一条路径可选到，无重复项、无遗漏（选项总数与该楼栋下商铺记录数相等）
- AC-194-04（异常）：Given 用户选"商铺"后返回把第一级改为 "2" / When 查看下一级 / Then 选项按 2 栋重新加载，不残留商铺的原楼栋选项

### US-195: 商铺原地改库（须另行授权）
- 故事：As a 管理员, I want to 把测试环境清册中类型为商铺的记录原地改为楼栋"商铺"且不丢原楼栋/门牌信息, so that 库内结构与用户看到的一致（"楼栋里面显示商铺"）
- 关联需求：REQ-FUNC-188、REQ-NFUNC-036、REQ-FUNC-186、C-57；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-195-01：Given 用户已另行明确授权在测试环境执行 / When 修正完成 / Then 专有部分记录总数与修正前相等；已认证业主绑定数与修正前相等；楼栋为"商铺"的记录数等于修正前类型为商铺的记录数（授权前核对为 107）；其余记录改动数为 0
- AC-195-02：Given 修正完成 / When 检查每条商铺记录 / Then 每条仍可得到修正前的原楼栋/门牌（丢失数 = 0），且用户端第二级（US-194）与后台均能显示；id=4347 现为"商铺"，不再在 1 栋下
- AC-195-03（冲突，REQ-NFUNC-036）：Given 冲突预演发现某条改后专有部分标识与既有记录重复 / When 执行修正 / Then 整批不执行，数据库保持修正前状态（记录总数与各记录内容一致），输出冲突记录清单
- AC-195-04（幂等）：Given 修正已执行一次 / When 再次执行 / Then 新增记录数为 0，被改动记录数为 0
- AC-195-05（还原）：Given 修正前已生成备份 / When 按备份还原 / Then 还原后与修正前逐记录一致（差异 0），已认证绑定数不变
- AC-195-06（已认证与申诉不受影响）：Given 某商铺已有已认证产权业主、另有一条针对该商铺的待审申诉 / When 修正完成 / Then 该业主仍绑定同一记录（认证状态与角色不变，"我的房屋"中名称显示为修正后的名称），待审申诉仍可审核；后台楼栋过滤器可选"商铺"
- AC-195-07（授权）：Given 用户未另行授权 / When 开发与验收进行 / Then 不连接测试机、对任何环境的清册写入数为 0，交付说明写明"数据修正未执行，等待授权"；开发测试仅用合成数据

### US-196: 按新结构反向生成批量导入文件（须另行授权）
- 故事：As a 管理员, I want to 得到一份按新结构（楼栋"商铺"）从清册只读导出的批量导入文件，保存在服务器专用目录, so that 我日后可用（"同时也要反向生成批量导入文件，保存在服务器上，我以后有用"）
- 关联需求：REQ-FUNC-189、REQ-NFUNC-036、C-59、C-57；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-196-01：Given 商铺改库（US-195）已完成且用户另行授权导出 / When 导出完成 / Then 文件表头与现有导入模板一致；商铺记录的楼栋列均为"商铺"；专有部分记录数、业主数、手机号数（去重）与同一时点清册逐项相等（差 0）；导出前后清册记录数、业主数不变（只读）
- AC-196-02：Given 生成的文件 / When 通过现有批量导入预检 / Then 整个文件未被拒绝，失败行数为 0，预检期间清册无任何改变；原楼栋/门牌信息的体现方式按设计确认结果（Q-OA-27），且预检通过
- AC-196-03（保存与权限）：Given 文件已生成 / When 检查服务器 / Then 文件位于部署目录之外的专用目录，目录权限 700、文件权限 600，文件名含日期；该目录不在任何 Web 可访问路径下，通过站点 URL 无法取得该文件（返回 404/403）
- AC-196-04（一次性）：Given 已有一份日期文件 / When 清册随后发生变更 / Then 该文件内容不被自动覆盖或更新；再次导出生成新的日期文件名，不覆盖旧文件
- AC-196-05（不入库，C-59）：Given 含姓名与手机号的真实文件 / When 检索代码仓库（含 `project_workspace/`）、测试数据、报告与日志 / Then 检索不到该文件及其中的姓名、手机号，报告与日志只出现计数
- AC-196-06（边界）：Given 文件中楼层、户号、手机号形如 "0801"、"13800000000" / When 生成并再次预检 / Then 这些单元格仍为文本原值，无前导零丢失、无科学计数或 "3.0" 改写
- AC-196-07（异常/未授权）：Given 用户未授权导出，或导出中途读取失败 / When 开发验收或失败发生 / Then 未授权时不连接测试机、不生成含真实数据的文件；失败时无残缺文件被误作完整文件（失败给出明确信息，已生成的部分文件被清除或标记），清册写入数为 0

### US-197: 申诉列表显示审核所需信息
- 故事：As a 管理员, I want to 在申诉页看到申诉编码、申诉人账号与昵称、产权人名字、申诉时间、专有部分坐落, so that 我无需逐条点开就能核对（"我希望能有显示申述的编码，申述人的账号，姓名，申述的时候要提交产权人名字，申述的时间"）
- 关联需求：REQ-FUNC-190；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-197-01：Given 存在一条 id=123 的申诉，申请人账号 A001、昵称"小明"，申诉时填产权人名字"张三"，提交时间 2026-11-16 10:00 / When 管理员打开申诉列表 / Then 该行显示"申诉编码"`#123`、账号 A001、"昵称"列"小明"、"产权人名字"列"张三"、申诉时间 2026-11-16 10:00、所申诉专有部分的坐落，以及缩略图（数量等于资料文件数）
- AC-197-02（边界）：Given 申请人无昵称 / When 查看 / Then 昵称列显示"未设置"，行内其余字段正常
- AC-197-03（旧申诉）：Given 本批上线前提交的申诉没有产权人名字 / When 查看 / Then 产权人名字列显示"未提供"，页面无报错
- AC-197-04（隐私，C-63）：Given 申请人账号绑定了手机号 / When 查看列表 / Then 手机号仍为脱敏形式，列表中无完整手机号明文
- AC-197-05（筛选不退化）：Given 管理员按状态筛选"待审" / When 查询 / Then 仅返回待审申诉，且每行仍含上述全部字段

- AC-198-02（pdf，Q-OA-09=A）：Given 申诉含 1 个 pdf 与 1 张图片 / When 查看列表与点击 pdf / Then pdf 显示文件图标+文件名（图片显示真实缩略图）；点击后弹出可预览层；预览失败时给出下载入口

- AC-198-05（本人）：Given 申请人本人 / When 打开自己申诉的资料 / Then 可以查看（沿用现有策略）；缩略图与大图地址不出现在任何公开可访问页面

### US-199: 申诉时提交产权人名字

- AC-199-02（必填）：Given 产权人名字为空或仅含空格 / When 提交 / Then 被拒绝（400），提示"请输入产权人名字"，不产生申诉
- AC-199-03（边界）：Given 名字去首尾空格后恰为 64 字 / When 提交 / Then 成功；Given 65 字 / Then 被拒绝并提示长度限制，不产生申诉

### US-200: 认证产权须输入姓名，姓名与手机号同一业主才自动绑定
- 故事：As a 登录用户, I want to 认证时输入姓名，并在姓名与我绑定的手机号和清册同一业主一致时自动绑定, so that 认证更准确（"只有姓名、绑定的手机号和业主清册上这个业主信息对应的时候，才会自动绑定"）
- 关联需求：REQ-FUNC-193、REQ-FUNC-194、REQ-NFUNC-037、C-61；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-200-01（正常）：Given 清册某专有部分业主甲姓名"张三"、手机号 13800000001，用户 U 账号已验证手机号 13800000001 / When U 选该专有部分并输入姓名"张三" / Then 自动认证为产权业主；该专有部分无其他认证者时 U 成为户主
- AC-200-02（姓名缺失）：Given 请求不含姓名或姓名为空/仅空格（含旧版客户端） / When 提交认证 / Then 返回 400，提示"请输入姓名"，不认证、不发起比对
- AC-200-03（姓名不一致）：Given 同 AC-200-01 但输入"张四" / When 提交 / Then 不认证，提示转入申诉流程（US-201），响应不含"张三"或手机号
- AC-200-04（同一业主，边界）：Given 同一专有部分有业主甲"张三"/13800000001 与业主乙"李四"/13800000002，U 手机号 13800000002 但输入"张三" / When 提交 / Then 不认证（姓名与手机号分属不同业主）；输入"李四"则认证
- AC-200-05（空格口径）：Given 输入"　张三 "（含全角空格与首尾空格） / When 提交 / Then 去首尾空格并归一后逐字相同，认证通过；输入"张 三"（中间空格）则不通过；不做模糊匹配（"张三丰"不匹配"张三"）
- AC-200-06（清册姓名为空）：Given 该专有部分业主姓名为空、手机号与 U 一致 / When U 输入任意姓名 / Then 不自动认证，转入申诉流程
- AC-200-07（统一失败响应，REQ-NFUNC-037）：Given 姓名错、手机号错、专有部分无该业主、清册姓名为空四种失败 / When 分别提交 / Then 四种响应的状态码与提示文案完全一致，无法区分原因
- AC-200-08（限频）：Given 同一用户 1 小时内已提交 30 次认证 / When 提交第 31 次 / Then 被限频拒绝（与现有行为一致），不加严
- AC-200-09（自动绑定通路不变，Q-OA-23=A）：Given 新用户用清册内登记的手机号注册或绑定手机号 / When 验证码验证通过 / Then 仍按手机号自动绑定其清册内专有部分，无姓名输入（保持 C-61 既定时机）

### US-201: 核对不一致转入申诉并上传资料
- 故事：As a 登录用户, I want to 姓名或手机号不一致时被引导到申诉并上传产权证明, so that 我仍有办法认证（"如果不一致就导入到申诉的流程上传资料"）
- 关联需求：REQ-FUNC-195；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-201-01：Given 认证核对失败 / When 用户看到失败提示并选择申诉 / Then 进入申诉表单，已选专有部分与已输入姓名保留，可上传 1~5 个资料（jpg/png/pdf，单个 ≤10 MB）并提交，申诉状态为待审
- AC-201-02（不泄露）：Given 核对失败 / When 查看提示 / Then 提示不包含清册中该专有部分的业主姓名、手机号或"姓名错/手机号错"的区分
- AC-201-03（重复）：Given 该用户对同一专有部分已有一条待审申诉 / When 再次提交 / Then 被拒绝并提示已有待审申诉（沿用现有规则），不产生第二条
- AC-201-04（资料不合格）：Given 上传 6 个文件或含非 jpg/png/pdf 或超过 10 MB 的文件 / When 提交 / Then 被拒绝并提示对应原因，不产生申诉

### US-202: 无手机号用户用姓名 + 产权证明认证
- 故事：As a 无手机号用户（微信一键登录未取得手机号）, I want to 只输入姓名并上传产权证明完成认证申请, so that 我无需先绑定手机号（"只输入名字，那就必须要上传产权证明"）
- 关联需求：REQ-FUNC-196、REQ-FUNC-195；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-202-01：Given 账号无已验证手机号 / When 用户选专有部分、输入姓名并提交认证 / Then 不返回 409 `PHONE_REQUIRED`，不自动认证，直接进入申诉流程；提交申诉（含 ≥1 个资料）后状态为待审

### US-203: 申诉通过后追加产权人到业主清册
- 故事：As a 管理员, I want to 通过申诉时把新的产权人名字和联系电话追加到清册, so that 清册与实际产权人一致（"一旦申诉成功……就需要把对应的新的产权人名字，联系电话更新到业主清册中"）

- AC-203-01（正常）：Given 申诉人账号手机号 13800000009，申诉的产权人名字"王五"，该专有部分清册原有业主"张三" / When 管理员通过申诉 / Then 申诉人被认证为产权业主；清册该专有部分新增业主"王五"及号码 13800000009；"张三"及其号码与已认证身份均保持不变
- AC-203-02（无手机号，Q-OA-16=A）：Given 申诉人账号无手机号 / When 管理员通过 / Then 清册新增业主"王五"、不写电话；申诉处理页提示"该产权人无联系电话"；认证成功
- AC-203-03（同名）：Given 该专有部分已有业主"王五"（无号码） / When 通过申诉人"王五"的申诉 / Then 不新增第二个"王五"，为已有"王五"追加申诉人的号码

- AC-203-05（失败回滚，Q-OA-18=A）：Given 清册更新过程失败 / When 管理员通过 / Then 申诉保持待审并提示失败原因，认证关系未建立，清册无部分写入

- AC-203-08（审计 `[INFERRED]`）：Given 一次追加更新完成 / When 查看审计日志 / Then 有一条记录含操作人、申诉编码、专有部分、更新类型"追加"、更新前后姓名、脱敏手机号（不含完整号码）、时间与结果
- AC-203-09（拒绝不更新）：Given 管理员拒绝申诉并填写原因 / When 拒绝完成 / Then 清册无任何变化

### US-205: 授予席位不再受"开始日早于今天"限制
- 故事：As a 管理员, I want to 授予任期开始日早于今天但未来仍有任期的席位, so that 能补录业委会成员（"授予席位时，不应该以授予时间早于当前作为限制，只要未来还有任期，就可以授予"）
- 关联需求：REQ-FUNC-199；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-205-01：Given 配置任期 36 个月，今天 2026-11-16，管理员授予开始日 2025-01-01（推算结束日 2028-01-01，晚于今天） / When 授予 / Then 成功，席位记录的开始日为 2025-01-01、结束日为 2028-01-01，不再返回"任期开始日不得早于今天"
- AC-205-02（任期已结束）：Given 开始日 2020-01-01（推算结束日 2023-01-01） / When 授予 / Then 被拒绝，提示"按配置任期，该席位已于 2023-01-01 结束，不能授予"，不产生席位
- AC-205-03（边界：结束日等于今天）：Given 推算结束日恰为 2026-11-16 / When 授予 / Then 被拒绝并给出同样的提示；Given 推算结束日为 2026-11-17 / Then 授予成功
- AC-205-04（已有席位不绕过）：Given 该用户已有有效席位 / When 授予补录席位 / Then 返回 409 `ALREADY_SEATED`，不产生新席位
- AC-205-05（人数上限不绕过）：Given 该身份在任人数已达上限 / When 授予补录席位 / Then 返回 409 `CAP_REACHED`
- AC-205-06（权限）：Given 非管理员账号或未登录者 / When 调用授予席位 / Then 被拒绝（401/403），不产生席位
- AC-205-07（不追溯）：Given 补录开始日早于授予时间的席位 / When 授予完成 / Then 开始日之后、授予之前已发起/已通过的决议、投票、审批的状态与结果均不变

### US-206: 未来起始日的席位在开始日前不生效

- AC-206-02（到期任务）：Given 存在开始日在将来的席位 / When 到期任务运行 / Then 该席位不被置为已到期；结束日已过的席位仍被置为已到期
- AC-206-03（授予即生效）：Given 开始日为今天或更早的席位 / When 授予成功 / Then 该用户立即享有身份与权限（与变更前一致，不退化）

- AC-206-05（边界）：Given 开始日恰为今天 / When 授予 / Then 视为已生效，立即享有身份与权限
