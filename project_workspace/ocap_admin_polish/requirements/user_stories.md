### US-132: 专有部分按"1栋1单元1层101号"格式生成
- 故事：As a 管理员, I want 专有部分标识按"楼栋单元楼层户号"直接连接并自动补全"栋/单元/层/号"后缀, so that 清册中的专有部分读起来美观清晰（`"我希望显示1栋1单元1层101号"`）
- 关联需求：REQ-FUNC-123；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-132-01：Given 楼栋"1栋"、单元"1单元"、楼层"1"、户号"101" / When 生成专有部分标识 / Then 标识为 `1栋1单元1层101号`，不含"-"
- AC-132-02：Given 车位：楼栋"1栋"、单元为空、楼层"负1"、户号"924" / When 生成标识 / Then 标识为 `1栋负1层924号`，单元为空段被跳过，无多余字符
- AC-132-03：Given 商铺：楼栋"10栋"、单元为空、楼层"1"、户号"1" / When 生成标识 / Then 标识为 `10栋1层1号`
- AC-132-04：Given 楼栋"10栋"、单元"3单元"、楼层"10"、户号"1001"（实测旧标识 `10栋-3单元-10-1001`） / When 按新规则生成 / Then 标识为 `10栋3单元10层1001号`
- AC-132-05：Given 楼栋为空或户号为空 / When 保存或导入 / Then 仍按基线规则被拒绝（楼栋、户号必填；错误原因指明缺少的字段），生成规则不改变必填校验（C-32）

### US-133: 边界取值的后缀补全规则
- 故事：As a 管理员, I want 对"整栋""A-088""负1"、已带后缀等各类取值都有确定的补后缀规则, so that 不同写法的数据生成的标识可预期、不被误改
- 关联需求：REQ-FUNC-124；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-133-01：Given 以下输入（楼栋/单元/楼层/户号）：`1栋 / 1单元 / 1层 / 101号`（四段均已带后缀） / When 生成标识 / Then 结果 `1栋1单元1层101号`，后缀不重复（不出现"1层层""101号号"）
- AC-133-02：Given 楼栋"1"、单元"1"、楼层"1"、户号"101"（均为纯数字、无后缀） / When 生成标识 / Then 结果 `1栋1单元1层101号`，与 AC-133-01 的结果相同
- AC-133-03：Given 实测样例 楼栋"建设南路146号"、单元空、楼层空、户号"整栋"（旧标识 `建设南路146号-整栋`） / When 生成标识 / Then 结果 `建设南路146号整栋`：楼栋含非数字且不以"栋"结尾，保持原样；户号"整栋"为非数字，保持原样；空段跳过
- AC-133-04：Given 实测样例 楼栋"圣灯路155号"、单元空、楼层"1"、户号"1层"（旧标识 `圣灯路155号-1-1层`） / When 生成标识 / Then 结果 `圣灯路155号1层`：户号以"楼层值+层"（"1层"）开头，楼层段不再单独输出，户号"1层"保持原样；结果中"层"字出现次数 = 1，不出现 `圣灯路155号1层1层`；楼层字段原值仍为"1"（已确认，用户 Q-AP-01=B，2026-11-11 "全部按照推荐"）；该记录出现在重新生成的核对清单中（见 AC-134-05）
- AC-133-05：Given 楼层"负1"、其余为 楼栋"1栋"、户号"924" / When 生成标识 / Then 结果 `1栋负1层924号`（"负"开头的数字按纯数字处理）；Given 楼层"-1"或"B1" / When 生成标识 / Then 保持原样，结果 `1栋-1924号`、`1栋B1924号`（已确认，用户 Q-AP-02=A，2026-11-11 "全部按照推荐"）
- AC-133-06：Given 楼栋"车库"、单元空、楼层空、户号"A-088" / When 生成标识 / Then 结果 `车库A-088`（均含非数字，保持原样）
- AC-133-07：Given 楼栋" 1栋 "（首尾含空格）、单元空、楼层空、户号"101" / When 生成标识 / Then 首尾空格被去除，结果 `1栋101号`；Given 楼层"3.0" / When 生成标识 / Then 视为非纯数字，保持原样"3.0"，不补"层"，不被改写成"3"
- AC-133-08：Given 实测样例 楼栋"建设南路160号"、单元空、楼层"1"、户号"1层A"，以及同楼栋 户号"1层B" / When 生成标识 / Then 结果分别为 `建设南路160号1层A`、`建设南路160号1层B`（户号以"1层"开头，楼层段省略，户号保持原样），两条标识互不相同，无冲突（用户 Q-AP-01=B）
- AC-133-09：Given 楼栋"建设南路160号"、单元空、楼层"2"、户号"1层"（户号不以"2层"开头） / When 生成标识 / Then 楼层段不省略，结果 `建设南路160号2层1层`（楼层"2"补"层"，户号保持原样）；规则判定仅取决于"户号是否以楼层值+层开头"，可据此逐条核对

### US-134: 现有清册数据按新规则重新生成
- 故事：As a 管理员, I want 上线时清册中全部现有专有部分的标识自动按新规则重新生成, so that 已导入的数据（测试环境 5742 条）立即呈现新格式，不需要重新导入
- 关联需求：REQ-FUNC-125、REQ-NFUNC-19、REQ-NFUNC-23；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-134-01：Given 测试环境 5742 条专有部分（旧格式如 `10栋-3单元-10-1001`、`1栋-负1-924`、`10栋-1-1`、`建设南路146号-整栋`） / When 本变更上线并完成重新生成 / Then 条数仍为 5742，上述四条依次变为 `10栋3单元10层1001号`、`1栋负1层924号`、`10栋1层1号`、`建设南路146号整栋`；清册中含"-"分隔旧格式的标识数量 = 0（户号本身含"-"的值如"A-088"除外）；样例 `圣灯路155号-1-1层` 变为 `圣灯路155号1层`、`建设南路160号-1-1层A` 变为 `建设南路160号1层A`
- AC-134-02：Given 上线前后 / When 比对楼栋、单元、楼层、户号四个字段 / Then 全部字段原值不变（差异条数 = 0，C-31）；类型、面积、业主、手机号、房屋关系、申诉、席位的条数差 = 0，悬空引用 = 0（REQ-NFUNC-19）
- AC-134-03：Given 重新生成已完成 / When 再次执行重新生成 / Then 被修改记录数 = 0（幂等）
- AC-134-04：Given 两条不同记录重新生成后标识相同（如楼层"1"+户号"101"与楼层"1层"+户号"101号"） / When 执行重新生成 / Then 整批不生效、清册数据保持上线前状态不变，并列出全部冲突记录（旧标识、各字段）；错误信息含冲突记录数（已确认，用户 Q-AP-03=A）；PM 在测试环境按新规则只读模拟 5742 条，冲突数 = 0
- AC-134-05：Given 重新生成成功 / When 管理员查看结果 / Then 能得到"户号非纯数字记录"核对清单（保留清单，改写口径：Q-AP-01=B 使"1层"类户号已按规则输出，不再属于"需人工关注的异常"，清单仅供抽查）：列出户号非纯数字（如"整栋""A-088""1层""1层A"）的记录数量与明细（旧标识、新标识、四个字段原值）；测试环境 PM 只读模拟为 27 条，以上线时实测为准；清单本身不修改数据；户号全为纯数字的记录不进入清单
- AC-134-06：Given 5742 条专有部分 / When 执行重新生成 / Then 在测试环境耗时 ≤ 60 秒 [INFERRED 数值，REQ-NFUNC-23]

- AC-135-02：Given 用户通过逐级选择或自动绑定与该专有部分建立了关系 / When 用户打开 Web 个人中心、我的房屋，或注册完成提示，以及小程序相应页面与自动绑定提示 / Then 专有部分均显示 `1栋1单元1层101号`，与管理端同一记录的显示逐字一致

### US-137: 批量导入按新规则分组与匹配
