# 需求规格说明书：身份文案、列表对齐与申诉审核表格化

> 本文档只描述系统应当做什么，不含实现设计与技术选型。
> 编号接续全项目既有最大号：REQ-FUNC 自 276、REQ-NFUNC 自 055、约束自 C-96、US 自 282（依据 `ocap_approval_finality` 的 REQ-FUNC-275 / C-95 / US-281 与 `ocap_profile_ux` 的 REQ-NFUNC-054）。
> 本批为纯展示层体验修正，不新增业务能力。
> 状态 APPROVED：Q-UX-01 ~ Q-UX-07 已由用户于 2026-11-21 确认完毕（D-01 ~ D-09），进入开发。

## 执行摘要

- 业务背景（用户原文，2026-11-21）：用户提出 5 组体验问题并要求“先整理我的变更需求，拆分呈用户故事。我确认后再开始开发”。原话要点：
  1. “我的身份与房屋页面，汇总身份的字体太小，可以大一点。改为业委会主任，其他身份也相应写全，比如业委会副主任，业委会委员，业主代表等等。另外决议->公开决议里面的决议条目不要一字排开。应该把进行中和已结束区别开来。”
  2. “管理员后台，业主清册页面。搜索、过滤的控件最好能和下面的表格的对应列对齐。标的列间距做好预设。和上面的控件对齐。”
  3. “业主清册页面分页控件可以设置每页显示多少。”
  4. “产权申述审核页面优化一下UI布局，不要挤成一团在左侧。让它成为一个表格。也能分页显示。然后必要的信息要显示在这里，比如如果绑定了手机号码，也应该显示。头像、昵称等等。用户房屋关系页面也要对齐过滤控件和表的列。加一个控件过滤户号，或者使用专有部分标识。”
  5. “业委会席位页面的表格过滤器也和清册，房屋关系一样的要求。另外这一页控件错位了。修复一下UI。”
- 辅助证据：用户随消息提供的 3 张截图——身份页（“汇总身份：业主”字号明显偏小）、业主清册（筛选控件在表格上方未与列对齐、分页无每页条数）、业委会席位（控件与表格在左侧挤压、过滤器未对齐列）。
- 数量：功能需求 13 条（REQ-FUNC-276 ~ 288）/ 非功能需求 4 条（REQ-NFUNC-055 ~ 058）/ 约束 5 条（C-96 ~ C-100）；用户故事 9 条（US-282 ~ US-290）。
- 优先级：用户明确提到的均为 Must Have；本批无 Should Have 以外的推断项。全部条目标注来源为“用户原文”或“截图”，无 INFERRED 需求（0%）。
- 变更性质：以展示层为主；后端 3 处只读改动——申诉列表补 `avatar_url`、公开决议列表排序调整、房屋关系列表补“专有部分标识 / 户号”过滤参数；另有 1 次性的历史身份文案迁移（写操作，见 REQ-FUNC-277）。权限、状态机、审批口径均不变。
- 已确认（2026-11-21 用户答复）：身份全称用于所有“身份”展示位置且历史身份快照一并迁移（D-01、D-05）；公开决议采用页内两分区 + 进行中优先（D-02）；每页条数在四个管理列表统一启用（D-03）；房屋关系使用合并的“专有部分标识 / 户号”过滤控件（D-04）；对齐采用表格上方独立网格（D-06）；原关键词框收窄为“姓名 / 手机号”（D-07）；席位折叠区保持现状（D-08）；小项按默认（D-09）。
