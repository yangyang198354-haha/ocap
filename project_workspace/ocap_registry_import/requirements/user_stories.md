## 用户故事

### US-092: 查看导入格式说明
- 故事：As a 管理员, I want to 在清册页面看到批量导入支持的文件类型和格式要求, so that 我上传前知道怎么准备文件
- 关联需求：REQ-FUNC-083、REQ-FUNC-084；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-092-01：Given 管理员已登录并打开业主清册页面 / When 查看导入区域 / Then 页面显示：支持 .csv 与 .xlsx；文件不超过 5 MB、不超过 20000 行；Excel 只读第一个工作表；每一列的名称、是否必填（车位面积必填、业主姓名必填、手机号选填）、允许取值；以及"同一专有部分有多位产权业主时分多行填写、姓名相同视为同一位业主"的说明和示例
- AC-092-02：Given 非管理员用户（含产权业主、户主）或未登录者 / When 访问清册页面或其导入接口 / Then 被拒绝，不返回任何清册数据
- AC-092-03：Given 页面说明显示"文件不超过 20000 行" / When 管理员上传 20001 个数据行的文件 / Then 导入被拒绝，提示"文件行数超过 20000"，清册不发生任何改变（说明与实际规则一致）
- AC-092-04：Given 管理员上传 .xls、.pdf 等其他类型文件 / When 提交 / Then 被拒绝，提示"仅支持 xlsx 或 csv"，清册不发生任何改变
- AC-092-05：Given 管理员上传超过 5 MB 的文件 / When 提交 / Then 被拒绝，提示"文件超过 5 MB"，清册不发生任何改变

### US-093: 下载导入模板
- 故事：As a 管理员, I want to 在页面一键下载导入模板, so that 我按模板填写就能导入
- 关联需求：REQ-FUNC-085、REQ-FUNC-086、REQ-NFUNC-013；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-093-01：Given 管理员在清册页面 / When 点击下载 xlsx 模板 / Then 下载到的文件第一个工作表为数据表，表头含：楼栋、单元、楼层、户号、专有部分类型、专有部分面积（平方米）、业主姓名、手机号，并含示例行（至少一个专有部分占 3 行的示例、一个手机号为空的业主示例、一个车位示例）；另有"填写说明"工作表，排在数据表之后
- AC-093-02：Given 管理员在清册页面 / When 点击下载 csv 模板 / Then 下载到 UTF-8 编码的 csv，用 Excel 打开中文表头不乱码，含表头与示例行
- AC-093-03：Given 管理员把模板中的示例行删掉后填入真实数据 / When 上传 / Then 导入成功，不因模板结构（隐藏列、合并单元格、第二个工作表）而失败
- AC-093-04：Given 模板中的手机号、楼层、户号列 / When 管理员在 Excel 中填入 "0801"、"13800000000" / Then 导入后保存为 "0801" 与 "13800000000"，不出现前导零丢失或 "3.0" 这类被改写的值
- AC-093-05：Given 非管理员用户 / When 请求模板下载 / Then 被拒绝
- AC-093-06：Given 管理员使用旧版 5 列模板（楼栋、单元、楼层、户号、手机号）填好的文件 / When 上传 / Then 整个文件被拒绝，提示缺少的列名（专有部分类型、专有部分面积（平方米）、业主姓名）并提示"请使用新模板"，清册不发生任何改变（Q-RI-12=A）

### US-094: 批量导入——一个专有部分任意多位产权业主
- 故事：As a 管理员, I want to 在导入文件中为同一专有部分填写任意多位产权业主（手机号可不填）, so that 一户有一位到五六位甚至更多业主都能一次导入
- 关联需求：REQ-FUNC-083、REQ-FUNC-086、REQ-FUNC-087、REQ-FUNC-090、REQ-NFUNC-011、REQ-NFUNC-014、REQ-NFUNC-015；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-094-01：Given 文件中同一专有部分（楼栋 1、单元 2、楼层 3、户号 301）占 6 行，6 行姓名互不相同，其中 4 行有手机号且互不相同、2 行手机号为空 / When 导入 / Then 该专有部分登记 6 位产权业主，导入结果显示新增专有部分 1 个、业主 6 位，其中 4 位有手机号的业主凭各自手机号均可通过该专有部分的清册认证（US-021）
- AC-094-02：Given 文件中一个专有部分含 200 位产权业主（200 行，姓名互不相同，总行数未超过 20000） / When 导入 / Then 全部 200 位登记成功，管理端可查看并可编辑，不出现"超过 10 个"一类提示（REQ-NFUNC-011 验收样本）
- AC-094-03：Given 手机号单元格写为 "13800000000;13900000000"，业主姓名为"张伟" / When 导入 / Then 登记业主"张伟"一位，其手机号为两个（继承分号写法）
- AC-094-04：Given 非管理员用户 / When 调用批量导入 / Then 被拒绝，清册不发生任何改变
- AC-094-05：Given 同一专有部分在同一文件中出现两行姓名均为"张伟"、手机号相同 / When 导入 / Then 登记一位业主"张伟"、一个手机号，不报错，不产生重复记录
- AC-094-06：Given 导入完成 / When 查看审计日志 / Then 有一条导入记录，含操作人、时间、导入/更新/失败条数；其中不出现手机号明文与业主姓名
- AC-094-07：Given 文件含 20000 个数据行（含表头共 20001 行）、大小不超过 5 MB，且全部合法 / When 导入 / Then 20000 行全部被处理，导入结果中新增、更新、失败的行数合计为 20000，不在第 5001 行被截断，且在 60 秒内返回结果（REQ-NFUNC-015）
- AC-094-08：Given 某行业主姓名"王芳"、手机号为空，其余字段合法 / When 导入 / Then 该行导入成功，业主"王芳"登记为产权人且手机号为空，不提示"手机号为空"
- AC-094-09：Given 某行业主姓名为空（手机号非空，其余字段合法） / When 导入 / Then 该行失败，原因为"业主姓名不能为空"，其余合法行照常导入（Q-RI-13=A）

### US-095: 单条登记产权业主（数量不限，姓名必填、手机号选填）
- 故事：As a 管理员, I want to 在页面为一个专有部分登记任意多位产权业主（姓名必填、手机号选填）, so that 单条维护也不受数量限制
- 关联需求：REQ-FUNC-087、REQ-FUNC-090、REQ-FUNC-095；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-095-01：Given 管理员打开某专有部分的业主登记 / When 填写 12 位业主（姓名不同，手机号均合法）并保存 / Then 保存成功，该专有部分显示 12 位业主，不再提示"手机号须为不超过 10 个的列表"
- AC-095-02：Given 管理员为某业主填写了姓名与手机号 / When 保存并重新打开 / Then 姓名与完整手机号显示
- AC-095-03：Given 填写的手机号格式不正确 / When 保存 / Then 保存被拒绝，提示"手机号格式不正确"，该专有部分原有业主不变
- AC-095-04：Given 非管理员用户 / When 调用单条登记 / Then 被拒绝
- AC-095-05：Given 管理员删除某位业主并保存 / When 该业主此前已通过该手机号认证 / Then 其已认证身份保留（REQ-FUNC-033、C-22）；之后再用该手机号做新的认证比对则不再通过
- AC-095-06：Given 用户端任一页面、申诉审核页、审计日志页 / When 展示该业主信息 / Then 手机号显示为 "138****0000"，姓名不显示（REQ-NFUNC-012）
- AC-095-07：Given 管理员登记业主时姓名留空 / When 保存 / Then 保存被拒绝，提示"业主姓名不能为空"，该专有部分原有业主不变（Q-RI-13=A）
- AC-095-08：Given 管理员登记业主"王芳"，手机号留空 / When 保存 / Then 保存成功，重新打开后"王芳"显示且手机号为空

### US-096: 批量导入时记录专有部分类型与面积
- 故事：As a 管理员, I want to 在批量导入文件中为每个专有部分填写类型和面积, so that 清册记录住宅、公寓、商铺、车位及其面积
- 关联需求：REQ-FUNC-083、REQ-FUNC-088、REQ-FUNC-089；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-096-01：Given 文件中有 4 个专有部分，类型依次为 住宅、公寓、商铺、车位，面积分别为 89.50、60、（空）、12.50 / When 导入 / Then 4 个专有部分按所填类型登记，面积为 89.50、60.00、未登记、12.50
- AC-096-02：Given 新建专有部分的行类型为空 / When 导入 / Then 该行失败，原因为"专有部分类型为空"，其余合法行照常导入
- AC-096-03：Given 类型填写为集合以外的值（如"别墅"） / When 导入 / Then 该行失败，原因为"专有部分类型不在允许范围内（住宅、公寓、商铺、车位、其他）"
- AC-096-04：Given 面积填写为 "abc"、"-5"、"0" 或 "12.345" / When 导入 / Then 对应行失败，原因分别指明面积须为大于 0 的数值、最多 2 位小数
- AC-096-05：Given 同一专有部分的多行中类型互不相同（如一行住宅、一行商铺） / When 导入 / Then 该专有部分的所有行均失败，原因为"同一专有部分的类型不一致"，该专有部分不被写入
- AC-096-06：Given 文件缺少"专有部分类型"列 / When 导入 / Then 整个文件被拒绝，提示缺少的列名"专有部分类型"，清册不发生任何改变
- AC-096-07：Given 新建专有部分的行类型为"车位"、面积为空 / When 导入 / Then 该行失败，原因为"车位的专有部分面积不能为空"，其余合法行照常导入；类型为"住宅"、"公寓"、"商铺"或"其他"且面积为空的行导入成功（Q-RI-14=A：仅车位必填）

### US-097: 单条新增与修改专有部分类型、面积
- 故事：As a 管理员, I want to 在新增或编辑单个专有部分时选择类型并填写面积, so that 单条维护的记录与批量导入一致
- 关联需求：REQ-FUNC-088、REQ-FUNC-089、REQ-FUNC-095；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-097-01：Given 管理员打开"新增专有部分" / When 选择类型"商铺"、面积填 120.25 并保存 / Then 保存成功，列表该行显示类型"商铺"与面积 120.25
- AC-097-02：Given 新增时未选类型 / When 保存 / Then 保存被拒绝，提示"请选择专有部分类型"
- AC-097-03：Given 面积填写为非数值或超过 2 位小数 / When 保存 / Then 保存被拒绝，提示面积格式不正确，原记录不变
- AC-097-04：Given 清册列表有住宅与车位混合数据 / When 管理员按类型"车位"筛选 / Then 列表仅显示类型为车位的专有部分
- AC-097-05：Given 非管理员用户 / When 调用新增或修改 / Then 被拒绝
- AC-097-06：Given 管理员修改了类型或面积 / When 保存成功 / Then 审计日志新增一条清册变更记录（操作人、专有部分），且已认证的身份不受影响
- AC-097-07：Given 管理员新增类型为"车位"的专有部分且面积留空 / When 保存 / Then 保存被拒绝，提示"车位须填写专有部分面积"，清册不发生任何改变
- AC-097-08：Given 管理员新增类型为"住宅"的专有部分且面积留空，且不登记业主 / When 保存 / Then 保存成功，该专有部分面积显示"未登记"（Q-RI-13=A、Q-RI-14=A：新增专有部分不要求业主，仅车位面积必填）

### US-098: 登记与选择车位、商铺等无单元/楼层结构的专有部分

- 关联需求：REQ-FUNC-091、REQ-FUNC-010（变更）；优先级：Must Have；故事点：5 [ESTIMATE]
- 备注：Q-RI-05=B 已确认。
- AC-098-01：Given 管理员新增类型为"车位"、楼栋"车库"、户号"A-088"、面积 12.50 的专有部分，单元与楼层留空 / When 保存 / Then 保存成功，专有部分标识为"车库-A-088"，不含空层级产生的多余分隔符
- AC-098-02：Given 注册用户选择专有部分，清册中楼栋"车库"下所有专有部分的单元与楼层均为空 / When 选定楼栋"车库" / Then 单元、楼层两级不出现，直接列出户号选项；选定后可提交认证
- AC-098-03：Given 楼栋"1"下既有带单元、楼层的住宅又有无单元的商铺 / When 用户选定楼栋"1" / Then 单元选项仅列出有取值的单元，不出现空白选项，商铺仍可到达（路径由设计阶段确定，不得丢失）
- AC-098-04：Given 导入行缺少户号或缺少楼栋 / When 导入 / Then 该行失败，原因指明缺少的字段；单元或楼层为空不报错
- AC-098-05：Given 既有四级完整的专有部分（如"1-2-3-301"） / When 本变更上线后 / Then 其标识、认证与逐级选择行为不变
- AC-098-06：Given 导入文件中类型为"车位"、楼栋"车库"、户号"A-088"、单元与楼层为空、面积 12.50、业主"赵云"手机号为空的一行 / When 导入 / Then 导入成功，新增专有部分"车库-A-088"，业主"赵云"登记，导入结果失败行数为 0

### US-099: 重复导入同一专有部分——按业主姓名区分产权人
- 故事：As a 管理员, I want to 重复导入已有专有部分时，姓名不同即视为同一专有部分的另一位产权人、且不会误删业主, so that 补录信息安全
- 关联需求：REQ-FUNC-092、REQ-FUNC-098；优先级：Must Have；故事点：5 [ESTIMATE]
- 备注：Q-RI-06 已确认（按姓名区分、只增不删）；Q-RI-15=A（同名追加手机号）、Q-RI-16=A（仅按姓名区分）、Q-RI-17=A（同专有部分同手机号不同姓名则失败）已确认。
- AC-099-01：Given 专有部分 X 已登记业主"张伟""李娜"，文件中 X 只有业主"王强" / When 导入 / Then X 的业主为"张伟""李娜""王强"三位，导入结果将 X 计入"更新"
- AC-099-02：Given X 已有业主"张伟"（手机号 A），文件中 X 有业主"张伟"（手机号 B） / When 导入 / Then X 的业主仍为"张伟"一位，其手机号为 A 和 B 两个，业主总数不变（Q-RI-15=A）
- AC-099-03：Given X 已有类型"住宅"、面积 89.50，文件中 X 的类型"公寓"、面积 90.00 / When 导入 / Then X 的类型和面积改为文件所填值，导入结果列出 X 被修改的字段
- AC-099-04：Given 文件中 X 的类型、面积为空，X 已有值 / When 导入 / Then X 原有类型与面积保持不变
- AC-099-05：Given 文件中的专有部分在清册中已存在，且"李娜"此前已通过清册认证 / When 导入的文件中不含"李娜" / Then 李娜的业主记录与已认证身份保留（C-22）
- AC-099-06：Given 同一文件内同一专有部分的类型信息冲突 / When 导入 / Then 按 AC-096-05 拒绝该专有部分，不写入
- AC-099-07：Given X 已登记业主"张伟"（手机号 A），文件中 X 有业主"李娜"（手机号 A） / When 导入 / Then 该行失败，原因为"手机号已登记给同一专有部分的另一位业主"，X 的业主不变（Q-RI-17=A）
- AC-099-08：Given X 已登记业主"张伟" / When 导入文件中 X 有一行姓名为"张伟 "（末尾带空格）、一行姓名为"张伟（二）" / Then 前者与"张伟"视为同一位产权人，后者为新增的另一位产权人，X 共 2 位业主（Q-RI-16=A：比较仅去除首尾空格，由管理员自行加区分标记）

### US-100: 导入前预检与错误报告
- 故事：As a 管理员, I want to 导入前先预检并看到清晰的结果与错误清单, so that 我能先改好文件再正式导入
- 关联需求：REQ-FUNC-093、REQ-NFUNC-014、REQ-NFUNC-015；优先级：Should Have；故事点：5 [ESTIMATE]
