# 需求规格说明书：导航信息架构整合（Web + 微信小程序）

> 批次：ocap_navigation_ia（INCREMENTAL）。本文档只描述系统应当做什么，不含设计与技术选型。
> 用户明确要求"先整理我的需求，拆分用户故事。然后给我确认。确认后才开始开发"，本文档为待确认草稿。

## 执行摘要

- 业务背景：用户要求整理 Web 端与微信小程序的导航信息架构——收敛"我的房屋"下的二级菜单、把"待我审批的同住人申请"从卡片改为页内 Tab、重组右上角用户下拉菜单为"个人设置/系统设置"两组，并放慢下拉菜单动效（原文见 phase_status.md 的 `<request>`）。
- 数量：功能需求 19 条（REQ-FUNC-297 ~ 315）/ 非功能需求 3 条（REQ-NFUNC-061 ~ 063）/ 约束 4 条（C-362 ~ 365）/ 用户故事 12 个（US-299 ~ 310）。
- INFERRED：1 条（REQ-NFUNC-061），1 ÷ (19 + 3) = 1/22 = 4.5%，未超过画像 P5 的 20% 上限；Q2/Q3/Q4 已于 2026-11-22 由用户确认，原 3 条推断转为确定需求。
- 优先级规则（一次说明）：用户原文明确提到的功能为 Must Have；由原文推导、但用户未直接点名的条目为 Should Have。Q2/Q3/Q4 确认后相应条目升为 Must Have。Must Have 20 条（功能 18 + 非功能 2）/ Should Have 2 条（功能 1 + 非功能 1）。
- 阻断项：0 条。Q1 已于 2026-11-22 按用户选择 A 解决（二级菜单只保留"我的认证与申述"唯一申诉入口）；Q2/Q3/Q4 同轮确认。其余 Q5~Q8 为非阻断开放问题，按推荐默认执行。

## 超出范围

- 不调整小程序底部 tabBar（仍为：首页、决议、投票、我的）。
- 不新增界面风格主题，不改造现有主题选项（`MeStyle.vue`、`theme/`）。
- 不改变申诉、同住申请的提交/审批业务规则与后端权限（沿用 REQ-FUNC-289~296、C-359~361）。
- 不调整"我的房屋"以外的其他一级菜单（决议、投票/调查、报销/备用金、收入表、财务报表、待办、信息公开）的结构。
- 不做整站视觉样式改版；本批次只涉及菜单分组、Tab 与下拉动效。
- "财务报表"是否继续保留在小程序"我的"页，留待 Q5 确认，不在本批次改动其内容。
