## 用户故事

### US-150: 逐级选择房屋申请成为同住人（Web + 小程序）

- 故事：As a 注册用户, I want to 像认证产权时一样逐级选择楼栋、单元、楼层、户号来申请成为某套房屋的同住人, so that 我不必知道任何内部编号就能提交申请
- 关联需求：REQ-FUNC-142；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-150-01 [E2E]：Given 注册用户 U 已登录，专有部分 X 已有产权业主 / When U 在同住人申请页逐级选择 X 的楼栋、单元、楼层、户号并提交 / Then 创建一条状态为"待审批"的申请，页面提示"申请已提交，等待产权业主审批"；申请过程中页面没有任何要求输入"专有部分 ID"或其他内部编号的输入框
- AC-150-02 [E2E]：Given 专有部分 Y 当前没有任何产权业主 / When U 为 Y 提交同住人申请 / Then 提交被拒绝，提示该专有部分暂无产权业主、请先做产权认证，不创建申请（沿用 AC-024-06）
- AC-150-03 [E2E]：Given U 对 X 已有一条待审批的同住人申请 / When U 再次为 X 提交 / Then 提交被拒绝，提示已有待审批申请，申请总数不增加
- AC-150-04：Given U 已在微信小程序登录 / When U 在小程序打开"我的房屋"，选择"申请成为同住人"并逐级选择 X 后提交 / Then 结果与 AC-150-01 相同，小程序页面同样没有内部编号输入框

### US-151: 产权业主在首页看到并处理待审批的同住人申请（Web + 小程序）

- 故事：As a 产权业主（含户主）, I want to 在首页直接看到有多少同住人申请等我审批并一步进入审批, so that 申请人不会因为我不知情而长时间等不到回复
- 关联需求：REQ-FUNC-143；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-151-01 [E2E]：Given 专有部分 X 有 2 条待审批的同住人申请，X 的产权业主 O 已登录 / When O 打开首页 / Then 首页显示"待审批同住人申请：2"，点击后进入审批列表，列表恰有这 2 条，每条显示申请人昵称、房屋名称与提交时间，不显示申请人手机号明文
- AC-151-02 [E2E]：Given AC-151-01 的情形 / When O 通过其中 1 条后刷新首页 / Then 提示数量变为 1，被通过的申请人成为 X 的同住人；Given X 的另一位产权业主再处理这同一条申请 / Then 被拒绝，提示该申请已处理（沿用 AC-024-04）
- AC-151-03 [E2E]：Given 用户 V 不是 X 的产权业主（是 X 的同住人，或只是其他房屋的户主） / When V 打开首页，或直接请求审批 X 的申请 / Then 首页不显示该提示；审批请求被拒绝（HTTP 403），申请状态不变（沿用 AC-024-05）
- AC-151-04：Given 某产权业主名下的专有部分都没有待审批申请 / When 其打开首页 / Then 不显示"待审批同住人申请"提示
- AC-151-05：Given 产权业主 O 已登录微信小程序且 X 有待审批申请 / When 打开小程序首页 / Then 显示相同的待审批数量，并能进入审批列表完成通过或拒绝

### US-152: 申请人查看自己的同住人申请状态（Web + 小程序）

- 故事：As a 注册用户, I want to 在"我的房屋"里看到我提交过的同住人申请及其结果, so that 我知道申请是在等待、已通过还是被拒绝
- 关联需求：REQ-FUNC-144；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-152-01 [E2E]：Given U 向 X 提交了同住人申请，X 的产权业主尚未处理 / When U 打开"我的房屋"的"我的同住人申请" / Then 列表含一条：房屋名称（专有部分名称）、提交时间、状态"待审批"，处理时间为空
- AC-152-02 [E2E]：Given 产权业主拒绝了该申请 / When U 刷新列表 / Then 该条状态为"已拒绝"，处理时间显示"年-月-日 时:分"；Given U 再次为 X 提交 / Then 提交成功并出现一条新的"待审批"记录（沿用 AC-029-01）
- AC-152-03 [E2E]：Given 用户 W 从未提交过同住人申请，且他人有申请 / When W 打开该列表 / Then 列表为空并显示"暂无同住人申请"，不出现他人的申请
- AC-152-04：Given U 在微信小程序登录 / When 打开"我的房屋"的同住人申请列表 / Then 显示与 Web 相同的记录与状态

### US-153: 产权业主移除同住人、同住人主动退出（Web + 小程序）

- 故事：As a 产权业主或同住人, I want to 在页面上移除同住人或自己退出, so that 房屋的同住人名单可以及时更正
- 关联需求：REQ-FUNC-145、REQ-FUNC-150；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-153-01 [E2E]：Given 专有部分 X 有同住人 T，X 的产权业主 O 已登录 / When O 在 X 的同住人名单中选择 T 并在确认步骤点"确认" / Then T 不再出现在 X 的同住人名单中；T 在其他专有部分的身份不变；T 若无其他身份则回到"游客"（沿用 AC-029-02、029-05）
- AC-153-02 [E2E]：Given T 是 X 的同住人 / When T 在"我的房屋"选择退出 X 并确认 / Then T 的同住人身份解除，X 的同住人名单不再含 T；T 若无其他身份则回到"游客"（沿用 AC-029-03、029-05）
- AC-153-03 [E2E]：Given 用户为 X 的另一位同住人、其他房屋的户主，或管理员 / When 其尝试移除 X 的同住人 T / Then 被拒绝（HTTP 403），T 仍在名单中（沿用 AC-029-04）
- AC-153-04 [UI]：Given O 点击"移除"或 T 点击"退出" / When 弹出"后果 + 确认 / 取消"并点"取消" / Then 不发生任何变更，名单保持不变
- AC-153-05：Given 产权业主或同住人在微信小程序登录 / When 在小程序"我的房屋"执行移除或退出（含确认步骤） / Then 结果与 AC-153-01、AC-153-02 相同

### US-154: 只有现任业委会成员能发起报销与备用金

- 故事：As a 现任业委会成员, I want to 报销与备用金的发起入口和能力只属于业委会成员, so that 财务申请不会被无关用户创建
- 关联需求：REQ-FUNC-146；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-154-01 [E2E]：Given 普通产权业主、同住人或游客（非业委会成员）已登录，系统中存在可用的审批流程 / When 其直接请求发起报销或备用金 / Then 请求被拒绝（HTTP 403，提示"需要业委会成员身份"），不创建任何申请
- AC-154-02 [E2E]：Given 现任业委会委员已登录，已有可选审批流程 / When 其发起报销（填写事由、金额、发生日期、发票附件并选择流程） / Then 申请创建成功，状态为"审批中"；成员的审批、核销流程行为与改动前一致
- AC-154-03 [E2E]：Given 一位业主代表（不是委员、主任、副主任），以及一位席位已到期的前任成员 / When 各自直接请求发起报销或备用金 / Then 均被拒绝（HTTP 403），不创建申请
- AC-154-04 [UI]：Given 非成员用户在 Web 用户端或小程序登录 / When 查看导航与首页 / Then 看不到"报销/备用金"入口与"新建申请"按钮；Given 现任业委会成员登录 / Then 两者可见

### US-155: 小程序所有登录方式都保持 7 天

- 故事：As a 小程序用户, I want to 不论用微信、手机号验证码还是账号密码登录都保持 7 天登录, so that 我不必在手机上反复登录
- 关联需求：REQ-FUNC-147；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-155-01 [E2E]：Given 用户以小程序端身份用手机号验证码登录 / When 登录后 31 分钟内无任何操作，再发起一个需登录的请求 / Then 请求成功，仍处于登录状态（闲置超过 30 分钟不再退出）
- AC-155-02：Given 用户以小程序端身份用账号或手机号 + 密码登录，使用可控时钟 / When 在登录后 6 天 23 小时访问 / Then 访问成功；Given 登录已满 7 天后访问 / Then 被拒绝（HTTP 401），要求重新登录
- AC-155-03：Given 用户在 Web 用户端登录且未勾选"记住我"，或管理员登录管理后台 / When 闲置 31 分钟后操作 / Then 被拒绝并要求重新登录（Web 用户端与管理后台的规则不变，AC-069-01、069-05）

### US-156: 用户查看自己的产权申诉进度与结果（Web + 小程序）

- 故事：As a 注册用户, I want to 在"我的房屋"里看到我提交的产权申诉处于待审核、已通过还是已驳回及驳回原因, so that 我知道下一步该怎么做
- 关联需求：REQ-FUNC-148；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-156-01 [E2E]：Given U 为房屋 X 提交了产权申诉，管理员尚未处理 / When U 打开"我的房屋"的"我的申诉" / Then 列表含一条：房屋名称、提交时间、状态"待审核"，处理时间为空
- AC-156-02 [E2E]：Given 管理员驳回该申诉并填写了驳回原因 / When U 刷新列表 / Then 该条状态为"已驳回"，显示处理时间与管理员填写的驳回原因原文
- AC-156-03 [E2E]：Given 管理员通过了该申诉 / When U 刷新列表 / Then 该条状态为"已通过"；U 在 X 的身份出现在 US-157 的房屋列表中
- AC-156-04 [E2E]：Given 用户 W 从未提交过申诉，U 有申诉 / When W 打开该列表 / Then 列表为空并显示"暂无申诉"，不出现 U 的申诉
- AC-156-05：Given U 在微信小程序登录 / When 打开"我的房屋"的申诉列表 / Then 显示与 Web 相同的记录、状态与驳回原因

### US-157: 查看自己每套房屋的身份与汇总身份（Web + 小程序）

- 故事：As a 注册用户, I want to 在个人中心和"我的房屋"里看到我认证的每套房屋及我在其中的身份，并有一个汇总身份, so that 我清楚自己的权限，不会误以为户主只是同住人
- 关联需求：REQ-FUNC-149；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-157-01 [E2E]：Given 用户 U 在房屋 A 为户主、在房屋 B 为同住人 / When U 查看个人身份数据并打开 Web 个人中心、"我的房屋"、小程序"我的"页 / Then 三处都列出两行：A（户主）、B（同住人），汇总身份显示"户主"；重复刷新多次，结果顺序与汇总身份不变
- AC-157-02：Given 用户 U 同时是业委会副主任且在房屋 A 为户主 / When U 查看身份 / Then 汇总身份显示"副主任"，房屋行仍显示 A（户主）
- AC-157-03 [E2E]：Given 游客 G（没有任何认证房屋，无业委会席位） / When G 查看身份 / Then 汇总身份显示"游客"，房屋列表区显示"暂无已认证房屋"
- AC-157-04 [E2E]：Given 同一用户 U / When 管理员在注册用户列表（REQ-FUNC-136）查看 U 的身份 / Then 该标签与 U 本人看到的汇总身份一致
- AC-157-05：Given 管理员撤销了 U 在房屋 B 的认证 / When U 刷新个人中心 / Then 列表不再含 B；所有身份文字为中文，页面上没有任何编辑身份的控件

### US-158: 不可逆与影响面大的操作先确认（Web）

- 故事：As a 管理员或用户, I want to 在执行撤销、删除、作废、撤回、注销等操作前先看到后果并确认, so that 误点不会造成不可恢复的损失
- 关联需求：REQ-FUNC-150；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-158-01 [UI]：Given 管理员在"用户房屋关系"页点击某条认证的"撤销" / When 弹出确认框 / Then 框内写明后果（该用户将失去该房屋的身份；撤销户主认证会触发户主接任，席位可能失效），并有"确认"与"取消"；点"取消"后认证仍有效、没有新增审计记录
- AC-158-02 [E2E]：Given 管理员对某 `e2e_` 用户的认证完成确认 / When 确认生效 / Then 该用户在该房屋不再有身份，审计日志新增一条撤销认证记录（证明确认后的操作被执行）
- AC-158-03 [UI]：Given 管理员点击撤销业委会席位、删除专有部分、删除审批流程，或用户点击收入表作废、决议/报销/收入表撤回 / When 弹出"后果 + 确认 / 取消"并点"取消" / Then 不发生任何变更；点"确认"才执行
- AC-158-04 [UI]：Given 用户点击"注销账号" / When 弹出确认框 / Then 框内列出四项后果：户主身份将由他人接任、业委会席位失效、待处理的申请与申诉被关闭、账号不可恢复；点"取消"后账号仍可正常登录，点"确认"（并完成验证码）才注销

### US-159: 管理员按姓名/手机号/账号搜索并选择用户（赋予席位、配置审批人）

- 故事：As a 管理员, I want to 搜索并选择用户而不是手输用户 ID, so that 我不会因抄错 ID 而选错人
- 关联需求：REQ-FUNC-151；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-159-01 [E2E]：Given 管理员已登录，存在一位注册用户 P（`e2e_` 账号，清册实名已知，手机号后四位为 0001） / When 管理员在"赋予席位"页分别按账号、手机号后四位 0001、清册实名搜索 / Then 三次搜索的候选列表都包含 P，候选项显示昵称、清册实名（有则显示）、账号、脱敏手机号（如"138****0001"，不含明文）与最高身份
- AC-159-02 [UI]：Given 管理员选中候选项 P / When 返回表单 / Then 表单显示所选用户的昵称与最高身份供确认；页面上不存在"用户 ID"输入框，提交时也不要求填写任何数字 ID
- AC-159-03 [E2E]：Given 管理员选中一位游客（不是产权业主）并提交赋予委员席位 / When 提交 / Then 被拒绝，错误信息与改动前同类拒绝一致（席位须赋予有效产权业主），不创建席位
- AC-159-04：Given 搜索关键词没有匹配的用户 / When 搜索 / Then 候选区显示"无匹配用户"；Given 匹配结果超过一页 / Then 可翻页
- AC-159-05 [E2E]：Given 管理员在审批流程页添加审批人 / When 搜索并选中两位现任业委会成员后保存 / Then 流程的审批人列表显示这两人的昵称；选中非现任业委会成员时，沿用既有拒绝与错误信息
