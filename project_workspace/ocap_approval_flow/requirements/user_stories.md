# 用户故事 — 审批流程多步化与或/与签（ocap_approval_flow）

> 说明：本批次所有审批人角色均须为现任业委会成员（C-366）。发起人仅能对自己有权发起的单据类型发起审批；“管理员”指具备审批流程配置与审批查看权限的后台管理员。

## 角色 × 功能矩阵

| 角色 | 流程配置 | 发起与撤回 | 步骤审批 | 审批进度与时间线 |
|---|---|---|---|---|
| 管理员 | US-311、US-312 | — | — | US-317、US-318、US-319 |
| 发起人（业委会成员） | — | US-315、US-316 | US-313、US-314、US-321 | US-317、US-319、US-320 |
| 审批人（业委会成员） | — | — | US-313、US-314、US-315、US-321 | US-317、US-318、US-320 |
| 小程序端审批人/发起人 | — | US-320 | US-320 | US-317、US-320 |

## 用户故事

### US-311: 管理员创建带步骤与或/与策略的审批流程
- 故事：As a 管理员, I want to 在管理后台为一个单据类型创建包含多个有序步骤、每步有名称和审批人、并可为每步选择或签/会签的审批流程, so that 不同金额或不同事项可以按约定的多级审批规则流转。
- 关联需求：REQ-FUNC-316、REQ-FUNC-317、REQ-FUNC-318、REQ-FUNC-319、REQ-FUNC-325；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-316-01：Given 管理员已登录管理后台并进入审批流程配置页 / When 管理员新建流程，添加 2 个步骤，分别填写步骤名“财务初审”“主任终审”，各选择 1 名与 2 名现任业委会成员，并分别选择或签、会签 / Then 保存成功，流程详情按顺序显示 2 个步骤及其名称、审批人数与策略。
- AC-317-01：Given 管理员正在编辑流程步骤 / When 将任一步骤名称留空后保存 / Then 保存被拒绝，界面提示“步骤名称必填”，流程配置不发生变更。
- AC-318-01：Given 管理员正在编辑流程步骤 / When 某一步骤未选择任何审批人后保存 / Then 保存被拒绝，界面提示“每个步骤至少选择一名审批人”。
- AC-318-02：Given 管理员为某一步骤选择了非现任业委会成员 / When 保存该流程 / Then 保存被拒绝，提示该审批人不具备审批资格。
- AC-325-01：Given 一个已有 3 个步骤的流程 / When 管理员把第 3 步上移一位后保存 / Then 流程详情按新的顺序显示步骤，后续新发起的实例按新顺序执行。

### US-312: 管理员编辑、停用流程且不影响在办实例
- 故事：As a 管理员, I want to 修改或停用流程配置时不影响已经在审批中的单据, so that 在办单据仍按发起时的约定继续流转，不会因改配置卡住或换人。
- 关联需求：REQ-FUNC-326、REQ-FUNC-327；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-326-01：Given 一个流程有正在审批中的实例 / When 管理员为该流程新增一个步骤并保存 / Then 该在办实例的进度与待办保持不变，仍按发起时的步骤与审批人继续；之后新发起的实例才包含新步骤。
- AC-327-01：Given 升级前已存在“指定负责人”流程且配置了 2 名审批人、当前无在办实例 / When 升级完成后管理员查看该流程 / Then 该流程显示为 1 个步骤，步骤名称取原流程名称，策略为或签，审批人为原 2 名审批人，且可正常发起新的审批。
- AC-327-02：Given 升级前已发起且仍在审批中的指定负责人实例 / When 升级完成后该实例的审批人查看待办 / Then 该实例仍显示原审批人可审批，审批结果正常生效，不因升级丢失待办。

### US-313: 审批人处理“或签”步骤
- 故事：As a 当前步骤的审批人, I want to 在或签步骤中直接通过，且我的通过能让流程立即进入下一步, so that 不必等其他审批人也能推进事项。
- 关联需求：REQ-FUNC-319、REQ-FUNC-320、REQ-FUNC-322；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-320-01：Given 某或签步骤有 3 名审批人，均未操作 / When 其中 1 人点击通过并填写备注 / Then 该步骤状态为“已通过”，流程立即推进到下一步骤，下一步审批人收到待办，其余 2 人的该步待办消失。
- AC-320-02：Given 某或签步骤有 3 名审批人，均未操作 / When 其中 1 人拒绝并填写备注 / Then 该步骤仍为“进行中”，整单仍为“待审批”，其余 2 人仍可审批，时间线记录该拒绝动作与备注。
- AC-320-03：Given 某或签步骤 3 名审批人均已拒绝 / When 最后 1 人提交拒绝 / Then 该步骤判定为未通过，整单状态变为“拒绝”，时间线保留 3 条拒绝记录。

### US-314: 审批人处理“会签”步骤
- 故事：As a 当前步骤的审批人, I want to 在会签步骤中看到是否所有人都已同意, so that 只有全体同意时流程才推进，任何一人反对都能及时终止。
- 关联需求：REQ-FUNC-319、REQ-FUNC-321、REQ-FUNC-322；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-321-01：Given 某会签步骤有 2 名审批人 / When 其中 1 人通过 / Then 该步骤仍为“进行中”，整单仍为“待审批”，第 2 名审批人仍收到待办，时间线记录第 1 人的通过动作。
- AC-321-02：Given 某会签步骤有 2 名审批人，其中 1 人已通过 / When 第 2 人也通过 / Then 该步骤判定为通过，流程推进到下一步骤或整单通过。
- AC-321-03：Given 某会签步骤有 2 名审批人，其中 1 人已通过 / When 另 1 人拒绝并填写备注 / Then 该步骤判定为未通过，整单状态为“拒绝”，两步的动作与备注均出现在时间线中。

### US-315: 多步流程按顺序推进并在最后一步通过后整单通过
- 故事：As a 发起人, I want to 看到我的单据依次经过每一步审批，并在最后一步通过后生效, so that 我知道当前卡在哪一步、还需要谁处理。
- 关联需求：REQ-FUNC-322、REQ-FUNC-323；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-322-01：Given 一个 2 步流程的实例刚提交 / When 第 1 步尚未通过 / Then 只有第 1 步审批人收到待办，第 2 步审批人的待办中没有该单据。
- AC-323-01：Given 第 1 步已通过、第 2 步审批人全部满足该步策略 / When 第 2 步判定通过 / Then 整单状态为“通过”，对应业务（决议/支出/收入）按既有规则生效，时间线显示两步均已完成。

### US-316: 任一步骤未通过时整单拒绝并留痕
- 故事：As a 发起人, I want to 在某一步被拒绝时看到整单已结束及拒绝原因, so that 我按既有规则撤回重提或新建单据，而不是继续等待。
- 关联需求：REQ-FUNC-324；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-324-01：Given 一个多步实例进行到第 2 步 / When 第 2 步判定未通过 / Then 整单状态为“拒绝”，后续步骤不再产生待办，时间线保留第 1、2 步的全部动作与备注。
- AC-324-02：Given 某单据的审批结果为拒绝 / When 发起人尝试在原单上重新发起 / Then 系统拒绝该操作，并提示“该单据已结束，如需再次办理请新建”。

### US-317: 查看审批过程时间线
- 故事：As a 发起人或审批人, I want to 查看每一步的名称、到达时间、处理人、动作、时间与备注, so that 我能完整了解审批过程和每个人的意见。
- 关联需求：REQ-FUNC-328、REQ-FUNC-332；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-328-01：Given 一个已进行到第 2 步的实例 / When 有权限的查看人打开审批详情 / Then 时间线按步骤顺序显示第 1 步的名称、到达时间、每位审批人的通过/拒绝、动作时间与备注，第 2 步显示到达时间与当前待处理人，未到达步骤显示“未开始”。
- AC-328-02：Given 某步骤尚未到达 / When 查看人打开时间线 / Then 该步骤不显示到达时间或处理人，状态为“未开始”。
- AC-328-03：Given 审批人提交通过或拒绝 / When 其填写了 300 字备注 / Then 该备注完整显示在时间线对应动作下；若未填写备注，则显示为空，不影响提交。

### US-318: 审批过程仅对有权限的人可见
- 故事：As a 管理员, I want to 审批过程只对发起人、相关审批人和有权限的管理员可见, so that 审批意见不会泄露给无关用户。
- 关联需求：REQ-FUNC-329；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-329-01：Given 用户是该实例的历史审批人但当前步骤已不由其处理 / When 其打开该实例详情 / Then 可查看完整时间线与备注。
- AC-329-02：Given 用户既不是发起人、也不是任何步骤审批人、且无审批查看权限 / When 其请求该实例详情或时间线 / Then 请求被拒绝，界面不展示任何审批动作或备注。

### US-319: Web 用户端查看进度与处理待办
- 故事：As a Web 用户端用户, I want to 在“待我审批”中只看到当前轮到我的单据，并能查看完整进度, so that 我不会被尚未轮到的步骤干扰。
- 关联需求：REQ-FUNC-330；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-330-01：Given 一个 2 步流程实例处于第 1 步 / When 第 2 步审批人打开“待我审批” / Then 列表中没有该单据；第 1 步审批人打开时可见该单据。
- AC-330-02：Given 有权限的查看人在 Web 管理后台打开审批实例 / When 查看详情 / Then 显示与用户端一致的步骤进度与时间线内容。

### US-320: 小程序端审批与查看进度
- 故事：As a 小程序端审批人, I want to 在小程序中处理待办并查看审批进度, so that 我不打开电脑也能及时审批。
- 关联需求：REQ-FUNC-331；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-331-01：Given 小程序端审批人是某实例当前步骤审批人 / When 其在小程序提交通过并填写备注 / Then 提交成功，整单/步骤状态与 Web 端一致，Web 端刷新后显示同一结果。
- AC-331-02：Given 小程序端用户是有权限的查看人 / When 其打开审批详情 / Then 显示与 Web 端一致的步骤名称、到达时间、处理人、动作与备注；无权限用户不展示时间线。

### US-321: 审批意见的记录与展示
- 故事：As a 审批人, I want to 在通过或拒绝时填写意见并被完整记录, so that 后续查看的人能理解我的判断依据。
- 关联需求：REQ-FUNC-332；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-332-01：Given 审批人打开待办 / When 其输入超过 500 字符的备注 / Then 系统拒绝提交或截断到 500 字符并明确提示，动作不会被记录为已提交。
- AC-332-02：Given 审批人未填写备注 / When 其直接提交通过或拒绝 / Then 动作提交成功，时间线中该动作备注显示为空。
