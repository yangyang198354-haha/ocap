## 部署步骤

### DEPLOY-001: 生成回滚锚点并快照后端与 Web
- 组件：`/home/yangyang/ocap/backend`（不含 venv/var/.env）、`/home/yangyang/ocap/web`
- 位置：目标机；`TS` 在本地取一次并全程复用
- 命令（要点）：
```bash
TS=$($OCAP_SSH 'date +%Y%m%d%H%M%S'); echo "ANCHOR_TS=$TS"
$OCAP_SSH "mkdir -p /home/yangyang/ocap/snapshots && tar -czf /home/yangyang/ocap/snapshots/backend-$TS.tar.gz -C /home/yangyang/ocap --exclude=backend/venv --exclude=backend/var --exclude=backend/.env backend && tar -czf /home/yangyang/ocap/snapshots/web-$TS.tar.gz -C /home/yangyang/ocap/web ocap && sha256sum /home/yangyang/ocap/snapshots/backend-$TS.tar.gz /home/yangyang/ocap/snapshots/web-$TS.tar.gz"
```
- 预期：两个 tar 生成且两端 SHA256 记录
- 回滚：无（锚点步骤）

### DEPLOY-002: 打包并上传后端与前端产物
- 位置：开发机 → 目标机
- 命令：本地 `tar -czf /tmp/backend-$TS.tar.gz -C . backend --exclude='backend/venv' --exclude='backend/var'`；`tar -czf /tmp/web-$TS.tar.gz -C frontend dist`；`scp` 到 `/home/yangyang/ocap/`；两端 `sha256sum` 比对
- 预期：SHA256 一致
- 回滚：ROLLBACK-004（删除本次上传的 tar 包，非必须；不影响运行）

### DEPLOY-003: 停止后端服务
- 位置：目标机
- 命令：`sudo systemctl stop ocap-backend; systemctl is-active ocap-backend || echo STOPPED`
- 预期：`STOPPED`
- 回滚：ROLLBACK-001（`sudo systemctl start ocap-backend`）

### DEPLOY-004: 解包新后端代码
- 位置：目标机
- 命令：`cd /home/yangyang/ocap && tar -xzf backend-$TS.tar.gz`（保留 `.env`、`venv`、`var`）
- 预期：`apps/accounts/migrations/0004_user_profile_fields.py` 存在
- 回滚：ROLLBACK-002（用锚点包恢复 backend 代码）

### DEPLOY-005: 应用数据迁移
- 位置：目标机
- 命令：`cd /home/yangyang/ocap/backend && set -a && . ./.env && set +a && venv/bin/python manage.py migrate accounts`
- 预期：`Applying accounts.0004_user_profile_fields... OK`
- 回滚：ROLLBACK-003（`migrate accounts 0003`）

### DEPLOY-006: 启动后端并确认存活
- 位置：目标机
- 命令：`sudo systemctl start ocap-backend; sleep 3; systemctl is-active ocap-backend; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9000/api/v1/users/1/profile`
- 预期：`active`；`401`（路由存在且要求登录）
- 回滚：ROLLBACK-002 + ROLLBACK-003（代码与迁移一起返回旧版）

### DEPLOY-007: 发布 Web 前端静态产物
- 位置：目标机
- 命令：
```bash
cd /home/yangyang/ocap && sudo rm -rf web/ocap.new && mkdir web/ocap.new && tar -xzf web-$TS.tar.gz -C web/ocap.new --strip-components=1 \
  && sudo rm -rf web/ocap.old && sudo mv web/ocap web/ocap.old && sudo mv web/ocap.new web/ocap \
  && sudo chown -R <OWN>:<OWN> web/ocap && echo WEB_SWAPPED
```
- 预期：`WEB_SWAPPED`；入口 `index.html` 的 SHA256 与本地 `dist/index.html` 一致
- 回滚：ROLLBACK-004（`mv` 回 `web/ocap.old` 或从 `web-$TS.tar.gz` 恢复）

### DEPLOY-008: 清理目标机上传包
- 位置：目标机
- 命令：`rm -f /home/yangyang/ocap/backend-$TS.tar.gz /home/yangyang/ocap/web-$TS.tar.gz`
- 预期：删除成功（快照保留）
- 回滚：不需要

## 回滚步骤（逆序）

### ROLLBACK-001: 启动旧服务（对应 DEPLOY-003 之前的状态）
- 类型：正式回滚
- 命令：`sudo systemctl start ocap-backend`
- 变量核验：无
- 预期：服务 active（旧代码仍可运行）

### ROLLBACK-002: 恢复后端代码快照（对应 DEPLOY-004/006）
- 类型：正式回滚
- 命令：`cd /home/yangyang/ocap && sudo rm -rf backend/apps backend/config backend/manage.py && tar -xzf snapshots/backend-$TS.tar.gz -C . --strip-components=0`
- 变量核验：`$TS` 为 DEPLOY-001 记录值；执行前 `echo` 完整命令并 `ls snapshots/backend-$TS.tar.gz`
- 预期：代码恢复；不触碰 `.env`、`venv`、`var`
- [MANUAL_ROLLBACK_REQUIRED: 若已产生新数据（签名档/实名开关/新头像），回滚代码不会删除已迁移字段；如需彻底回到旧结构，须先备份并执行 `migrate accounts 0003`，将丢失 0004 之后写入的签名与开关值]

### ROLLBACK-003: 反向迁移 accounts
- 类型：正式回滚（数据可丢失）
- 命令：`cd /home/yangyang/ocap/backend && set -a && . ./.env && set +a && venv/bin/python manage.py migrate accounts 0003`
- 变量核验：确认 0004 已应用（`showmigrations accounts`）
- 预期：`Unapplying accounts.0004_user_profile_fields... OK`
- [MANUAL_ROLLBACK_REQUIRED: 反向迁移会删除 signature / real_name_visible 列，部署后写入的数据不可恢复；执行前须 `mysqldump`（`--skip-ssl`，M-DE-008）备份 `accounts_user`]

### ROLLBACK-004: 恢复 Web 静态目录
- 类型：正式回滚
- 命令：`cd /home/yangyang/ocap/web && sudo rm -rf ocap && sudo mv ocap.old ocap && echo WEB_RESTORED`
- 变量核验：`ls -d /home/yangyang/ocap/web/ocap.old`
- 预期：旧 `index.html` SHA256 与 PRE-10 记录一致

## 不可逆步骤汇总

| 步骤 | 风险 | 处理 |
|---|---|---|
| DEPLOY-005 迁移 | 字段新增本身可逆，但部署后写入的数据在反向迁移时丢失 | 回滚前必须整库/表备份（ROLLBACK-003） |
| 前端替换 | 旧 assets 被删除后，仍打开的旧页面引用旧 chunk 会 404 | 保留 `ocap.old` 直至验证通过；用户刷新即恢复 |
