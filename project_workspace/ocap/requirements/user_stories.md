## 用户故事

### 域 A：注册与登录

### US-001: Web 端手机号 + 验证码注册
- 故事：As a 访客, I want to 仅用手机号和短信验证码在 Web 端完成注册（可选填邮箱）, so that 我无需设置密码即可拥有账号
- 关联需求：REQ-FUNC-001；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-001-01：Given 访客输入未注册的手机号并获取了短信验证码 / When 访客提交正确且在有效期内的验证码（不填邮箱） / Then 系统创建账号并生成账号标识，访客处于已登录状态，该用户身份为游客，注册过程中未要求设置密码
- AC-001-02：Given 访客输入未注册的手机号并获取了短信验证码 / When 访客提交错误的验证码，或提交已超过有效期的验证码 / Then 注册失败、不创建账号，界面提示验证码错误或已过期；错误次数达到上限后按已确认的规则限制继续尝试（REQ-NFUNC-001、C-06）
- AC-001-03：Given 访客注册时填写了邮箱 / When 注册成功 / Then 该邮箱仅作为未验证的资料项保存，不因注册而视为验证通过（验证见 US-007）
- AC-001-04：Given 访客输入的手机号已属于一个有效账号 / When 访客提交注册 / Then 系统不创建新账号，提示该手机号已注册并引导登录
- AC-001-05：Given 同一手机号短时间内多次获取验证码 / When 超出按已确认的规则允许的发送频率 / Then 系统拒绝再次发送并提示稍后重试（REQ-NFUNC-001、C-06）

### US-002: Web 端微信扫码登录
- 故事：As a 访客, I want to 在 Web 端用微信扫码登录, so that 我无需输入手机号或密码
- 关联需求：REQ-FUNC-002；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-002-01：Given 访客首次使用微信扫码、系统中尚无对应的微信账号 / When 访客在微信中确认授权 / Then 登录成功并创建账号，身份为游客，昵称取用其微信昵称，且不强制先验证手机号
- AC-002-02：Given 已有关联微信的账号 / When 该用户扫码并确认授权 / Then 登录进入该已有账号，不新建账号
- AC-002-03：Given 访客扫码后在微信中取消授权，或二维码已失效 / When 登录流程结束 / Then 不创建账号、不登录，Web 页给出授权被取消或二维码失效的提示，并可重新获取二维码
- AC-002-04：Given 微信用户未验证手机号 / When 该用户尝试做清册认证 / Then 系统要求先验证手机号（见 US-021）；在此之前其他登录后功能不受限

### US-003: 小程序端手机号登录
- 故事：As a 访客, I want to 在小程序中用手机号登录（验证码或密码）, so that 我可用手机号进入同一账号
- 关联需求：REQ-FUNC-003；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-003-01：Given 已注册的手机号 / When 用户提交正确且在有效期内的短信验证码 / Then 登录成功，进入该手机号对应的账号（与 Web 端同一账号，见 US-010）
- AC-003-02：Given 用户已设置密码 / When 用户提交手机号和正确密码 / Then 登录成功
- AC-003-03：Given 用户未设置密码 / When 用户选择密码方式登录 / Then 登录失败，提示该账号未设置密码，应使用验证码登录
- AC-003-04：Given 验证码错误、过期，或密码错误 / When 用户提交 / Then 登录失败并提示具体原因；连续错误按已确认的规则限制（REQ-NFUNC-001、C-06）
- AC-003-05：Given 手机号未注册 / When 用户用验证码登录 / Then 登录失败、不创建账号，提示该手机号未注册（登录不等于注册，注册见 REQ-FUNC-001）

### US-004: 小程序端微信一键登录
- 故事：As a 访客, I want to 在小程序中用微信一键登录, so that 我能快速进入系统
- 关联需求：REQ-FUNC-004；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-004-01：Given 首次微信登录、无对应账号 / When 用户同意一键登录 / Then 登录成功并创建账号，身份为游客，昵称取用微信昵称，不强制先验证手机号
- AC-004-02：Given 已有关联该微信的账号 / When 用户一键登录 / Then 进入该已有账号且不覆盖用户已修改的昵称（见 US-030）
- AC-004-03：Given 用户在微信授权弹窗中拒绝授权 / When 登录流程结束 / Then 不创建账号、不登录，页面提示授权失败，可重试

### US-005: Web 端账号 + 密码登录
- 故事：As a 注册用户, I want to 用系统生成的账号和密码在 Web 端登录, so that 我可不依赖验证码登录
- 关联需求：REQ-FUNC-005；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-005-01：Given 用户已设置密码且知道系统生成的账号 / When 提交账号和正确密码 / Then 登录成功
- AC-005-02：Given 账号不存在、密码错误，或账号未设置密码 / When 提交 / Then 登录失败，界面提示账号或密码错误（或未设置密码），不泄露账号是否存在以外的信息

### US-006: Web 端手机号登录（验证码或密码）
- 故事：As a 注册用户, I want to 在 Web 端用手机号加验证码或密码登录, so that 我登录方式灵活
- 关联需求：REQ-FUNC-006；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-006-01：Given 已注册的手机号 / When 提交正确且在有效期内的验证码 / Then 登录成功
- AC-006-02：Given 用户已设置密码 / When 提交手机号和正确密码 / Then 登录成功
- AC-006-03：Given 用户未设置密码 / When 选择密码方式登录 / Then 登录失败，提示应使用验证码登录
- AC-006-04：Given 验证码错误、过期或超过允许的错误次数 / When 提交 / Then 登录失败并提示原因；限制数值按已确认的规则（REQ-NFUNC-001、C-06）

### US-007: Web 端邮箱验证码登录与邮箱验证
- 故事：As a 注册用户, I want to 用邮箱验证码登录, so that 我可通过邮箱进入账号，且首次成功登录即完成邮箱验证
- 关联需求：REQ-FUNC-007；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-007-01：Given 账号资料中已填写某邮箱 / When 用户用该邮箱获取并提交正确且在有效期内的邮箱验证码 / Then 登录成功，进入填写该邮箱的账号，且该邮箱标记为已验证
- AC-007-02：Given 用户在邮箱登录页 / When 页面展示登录方式 / Then 邮箱登录仅提供验证码方式，不提供邮箱 + 密码登录入口；以邮箱 + 密码提交的尝试被拒绝
- AC-007-03：Given 邮箱未被任何账号填写 / When 用户用该邮箱获取验证码并提交 / Then 不创建账号、不登录，提示该邮箱未关联账号（任意邮箱登录即注册的方案已评估未采纳，Q22）
- AC-007-04：Given 邮箱验证码错误或过期 / When 提交 / Then 登录失败并提示原因；限制数值按已确认的规则（REQ-NFUNC-001 备注、C-06）

### US-008: Windows 微信桌面版一键授权登录
- 故事：As a 访客, I want to 在已开启微信桌面版的 Windows 电脑上点击"授权"免扫码登录, so that 登录更快捷
- 关联需求：REQ-FUNC-008；优先级：Must Have；故事点：8 [ESTIMATE]（可实现性不确定，故估高）
- 备注：**该能力的可实现性待架构阶段核实（C-05）**；核实不成立时，回到需求阶段与用户重新确认，本故事的 AC 届时调整。
- AC-008-01：Given 访客在 Windows 浏览器打开 Web 登录页且本机微信桌面版已开启并已登录 / When 访客点击"授权" / Then 无需扫码即登录成功，账号规则与微信扫码登录一致（首次登录创建游客账号，已有关联则进入原账号）
- AC-008-02：Given 本机未开启微信桌面版，或访客使用非 Windows 系统 / When 访客打开 Web 登录页 / Then 不展示一键授权入口（或该入口不可用），仍可使用其他登录方式
- AC-008-03：Given 访客点击"授权"后在微信桌面版中拒绝或超时未响应 / When 流程结束 / Then 不登录，页面提示授权未完成，可重试或改用其他方式

### US-009: 登录后设置密码
- 故事：As a 注册用户, I want to 注册后设置登录密码, so that 之后可用账号或手机号加密码登录
- 关联需求：REQ-FUNC-023；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-009-01：Given 用户已登录且未设置密码 / When 用户在密码和确认密码两处输入一致且符合已确认密码规则的密码并提交 / Then 密码设置成功，之后可用账号 + 密码、手机号 + 密码登录（US-005、US-006）
- AC-009-02：Given 用户已设置密码 / When 用户用邮箱 + 密码尝试登录 / Then 登录被拒绝，邮箱不适用密码登录（REQ-FUNC-007、Q21）
- AC-009-03：Given 用户在设置密码页 / When 密码与确认密码两次输入不一致并提交 / Then 设置失败、不修改账号凭据，界面提示两次输入的密码不一致
- AC-009-04：Given 用户在设置密码页 / When 用户未填写确认密码并提交 / Then 设置失败，界面提示需再次输入密码确认
- AC-009-05：Given 用户输入的密码不符合已确认的密码规则 / When 提交 / Then 设置失败，提示具体不符合的规则；密码规则（长度、复杂度等）由架构阶段提出并经用户确认后定稿（C-08），确认前不得自拟数值

### US-010: 手机号为账号唯一标识（三入口同一账号）
- 故事：As a 注册用户, I want to 无论从 Web、小程序还是微信进入都使用同一个账号, so that 我的身份与数据一致
- 关联需求：REQ-FUNC-024；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-010-01：Given 用户用手机号注册了账号并在资料中保有身份（如产权业主） / When 该用户分别从 Web 手机号登录、小程序手机号登录登录 / Then 两处进入同一账号，身份与资料一致
- AC-010-02：Given 微信用户验证并绑定了某手机号（该手机号无其他账号） / When 该用户之后通过微信登录和手机号登录 / Then 两种方式进入同一账号
- AC-010-03：Given 同一手机号 / When 任意入口尝试创建第二个账号 / Then 创建被拒绝；系统中同一手机号只存在一个有效账号（已注销账号除外，见 US-013）

### US-011: 管理员独立登录管理后台
- 故事：As a 管理员, I want to 用独立的账号和密码登录管理后台, so that 我能维护清册和审核申诉
- 关联需求：REQ-FUNC-025；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-011-01：Given 管理员账号由系统初始化或由已有管理员创建 / When 管理员在管理后台提交账号和正确密码 / Then 登录成功，进入管理后台
- AC-011-02：Given 普通注册用户（含已认证产权业主） / When 其用自己的账号登录管理后台 / Then 登录被拒绝，不获得任何管理权限
- AC-011-03：Given 访客 / When 访问任何注册入口 / Then 不存在注册管理员的入口；管理员账号仅可由系统初始化或已有管理员在后台创建
- AC-011-04：Given 管理员密码错误 / When 提交 / Then 登录失败并提示账号或密码错误；该登录结果记入审计日志（REQ-NFUNC-003 范围）

### 域 A-2：账号合并与手机号变更

### US-012: 微信绑定的手机号已属他人账号时合并
- 故事：As a 微信登录用户, I want to 绑定已属于另一账号的手机号时两个账号合并, so that 我不会拥有两个账号且已有数据不丢失
- 关联需求：REQ-FUNC-026；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-012-01：Given 微信账号 W 未验证手机号，手机号 P 已属于账号 A / When 用户对 P 验证通过 / Then W 与 A 合并为一个账号，合并规则按 US-015（资料与凭据）、US-016（身份）执行；合并后以 P 登录与以微信登录进入同一账号
- AC-012-02：Given 用户尝试绑定手机号 P / When 验证码错误或过期 / Then 不合并、不绑定，W 与 A 均保持不变，提示验证失败
- AC-012-03：Given 手机号 P 未属于任何其他账号 / When 验证通过 / Then 仅将 P 绑定到 W，不发生合并
- AC-012-04：Given 合并发生 / When 合并完成 / Then 审计日志记录合并操作（操作人、对象、时间、结果，REQ-NFUNC-003）

### US-013: 账号注销后同一手机号可作为全新账号再注册
- 故事：As a 曾注销账号的用户, I want to 用同一手机号再次注册, so that 我可重新使用系统
- 关联需求：REQ-FUNC-027；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-013-01：Given 手机号 P 的账号已注销 / When 用户用 P 注册 / Then 创建全新账号，身份为游客，不恢复原账号的任何身份、资料、绑定或户主身份，新账号与已注销账号无任何关联

### US-035: 清册手机号被修改或删除后已认证身份保留

- AC-036-03：Given U 是 X 的户主，且 X 另有一名或多名已认证的其他产权业主 / When 管理员撤销 U 在 X 的认证 / Then U 不再是 X 的产权业主；其他产权业主中认证时间最早者成为 X 的户主，其余产权业主身份不变，X 仍有且仅有一个户主（Q40=A，REQ-FUNC-020）；U 在其他专有部分的身份不变
- AC-036-04：Given 撤销已生效 / When U 再次通过清册手机号认证或申诉通过 / Then 可重新成为 X 的产权业主，按 US-021、US-026、US-023 的规则处理
- AC-036-05：Given 撤销已生效 / When 记录审计 / Then 审计日志新增一条记录，含操作人、对象、时间、结果 [INFERRED，见需求"待确认推断项"，REQ-NFUNC-003]

- AC-036-07：Given 撤销户主认证触发了户主接任（AC-036-03）/ When 接任完成 / Then 审计日志记录户主接任（REQ-NFUNC-003 范围已含"户主接任"，与 AC-027-04 一致）

### 域 D：账号注销

### US-031: 注销账号
- 故事：As a 用户, I want to 随时注销自己的账号, so that 我的个人数据被删除
- 关联需求：REQ-FUNC-017；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-031-01：Given 用户已登录 / When 用户发起注销并提交正确且在有效期内的验证码二次确认 / Then 注销立即生效：个人资料和登录凭据被删除，所有绑定与身份关系解除，用户被登出
- AC-031-02：Given 注销已生效 / When 查看业主清册 / Then 清册记录不变；历史业务记录保留但匿名
- AC-031-03：Given 验证码错误或过期 / When 提交注销 / Then 注销不生效，账号和数据不变，提示验证失败；错误次数限制按已确认的规则（REQ-NFUNC-001、C-06）
- AC-031-04：Given 用户是户主 / When 注销 / Then 户主按 US-027 处理
- AC-031-05：Given 用户有待审批的同住人申请或待审核的申诉 / When 注销 / Then 注销不受阻碍（无前提条件），相关待处理项一并关闭
