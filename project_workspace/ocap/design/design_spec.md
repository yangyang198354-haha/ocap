# ocap Web 前端设计规范（草案）：青年科技风

- **目标用户**：青年业主。要跟上潮流、有科技感，主要在手机上使用。
- **原型**：`prototype.html`（同目录），离线可直接打开。
  - 顶部工具栏可以切换 3 套风格、3 个页面（首页 / 决议 / 报销申请）和视图（桌面 / 手机）。
  - 快捷键：`1` `2` `3` 切换风格，`M` 切换视图。
  - URL 参数：`?theme=bento&page=claim&view=mobile`。
- **说明**：示例数据（"云栖苑"、人名、金额）都是虚构的，页面字段和业务规则来自现有前端与需求，比如决议的三类视图、两种审批方式、报销/备用金预借、金额两位小数、事由 1–500 字、附件类型。

## 1. 三套方案一览

| | A 霓虹玻璃 Neon Glass | B 极光 Bento Aurora | C 赛博终端 Cyber Grid |
|---|---|---|---|
| 关键词 | 深色、玻璃拟态、紫青霓虹、流光 | 浅色、极光渐变、便当格、大圆角 | 黑底网格、荧光绿、等宽数据、硬朗直角 |
| 参照气质 | Web3 钱包、Arc 浏览器、新能源车机 | Apple 发布会 Bento、Linear 官网浅色、小红书潮流卡片 | Vercel / Raycast 暗色、开发者终端、潮牌视觉 |
| 首页布局 | 12 栏：大 Hero + 待办侧栏，4 个数据卡，6 宫格入口 | 4 栏 Bento：Hero 和待办各占 2×2，深浅交替的数据块 | 12 栏紧凑网格，卡片左上角荧光角标，编号式入口 |
| 动效 | 背景光斑缓慢漂浮，Hero 流光描边，卡片悬浮上移 | 页面淡入，卡片悬浮上移，焦点光环 | 光标闪烁，扫描线，当前步骤脉冲 |
| 优点 | 科技感最强，"未来感"一眼就有 | 最耐看，明亮友好，信息层级清楚，长时间使用不累 | 辨识度最高，数据感强，很酷 |
| 风险 | 玻璃模糊耗电，低端安卓机可能卡；深色下表格多时密度高 | 潮流感依赖渐变和排版，平淡一点就像普通后台 | 偏小众、偏"程序员"，部分业主会觉得冷 |
| 适合 | 想要强烈视觉冲击 | **综合推荐**：青年潮流和公共事务的可信感能兼顾 | 想要个性鲜明的品牌 |

PM 的建议：**选 B 作为主方案**，把 A 的霓虹渐变用在少数亮点上（Hero、主按钮、数据高亮），并提供深色模式（深色模式就用 A 的配色）。这样潮流感、可读性、性能三方面兼顾得最好。最终由你决定。

### 2.2 字体与字号
- **中文**：优先 HarmonyOS Sans SC / MiSans，其次 PingFang SC，再其次微软雅黑。系统没有装时自动回退，不引入网络字体。
- **数字和金额**：等宽字体（JetBrains Mono / SF Mono），加上 `tabular-nums`，让金额小数点对齐，也增加科技感。
- **字号层级**：

  | 层级 | 字号/字重 | 手机端 |
  |---|---|---|
  | 页面标题 | 30 / 700，字距 -0.02em | 24 |
  | 区块标题 | 18 / 650 | — |
  | 正文 | 14–15 | — |
  | 辅助 | 12–13 | — |
  | 金额大字 | 26–30 / 700 | — |

- **C 方案**：标签、按钮、导航用等宽大写字母，字距 0.06em。

### 2.3 间距、圆角、阴影
- **间距**：以 4px 为基础单位。卡片内边距 20，网格间距 18（手机 12），页面边距 28（手机 16）。
- **圆角**：

  | 方案 | 卡片 | 输入框 | 按钮 |
  |---|---|---|---|
  | A | 20 | 14 | 14 |
  | B | 28（手机 22） | 16 | 胶囊形 |
  | C | 4 | 4 | 2，再加左上角角标 |

- **阴影**：
  - A：不用投影，靠细描边加主色辉光，主按钮有 30px 紫色辉光。
  - B：两层柔和投影，`0 1px 2px` 加 `0 12px 32px -12px` 靛蓝色。
  - C：不用阴影，用线框；聚焦和悬停时显示荧光描边。

### 2.4 动效
- 切换页面：0.35s 淡入，同时上移 6px。
- 卡片悬浮：0.2s 上移 2–3px。
- 装饰动效（光斑、流光、扫描线、光标、脉冲）全部支持 `prefers-reduced-motion`：系统开启"减少动态效果"时自动关闭。

## 3. 布局与响应式

- **断点**：内容区宽度小于 760px 时切换为手机布局。原型用的是容器查询 `@container`，落地时也可以改成 `@media`。
- **桌面端**：
  - 顶部玻璃（或半透明）吸顶导航，当前页高亮；
  - 内容区最大宽度 1180px；
  - 首页用网格，决议用双列卡片，报销表单为左表单右侧栏（审批预览加金额汇总）。
- **手机端**：
  - 隐藏顶部导航，改用**底部 5 个标签**：首页、决议、投票、报销、我的；
  - 内容单列，首页数据卡两列，快捷入口 3×2；
  - 报销页的"提交"按钮吸附在底部栏上方，单手就能点到。
- **解决现状的问题**：
  - 现在没有响应式，手机上 8 个导航链接会挤成几行。
  - 现在没有当前页高亮，三套方案都补上了。
  - 现在有 181 处内联样式，三套方案都改成用 token 驱动。

## 4. 关键组件规范
- **状态标签**：圆点加文字，再配浅色底或描边，不只靠颜色区分，色弱用户也能看懂。表决中用警示色，已通过用成功色，未通过用危险色。
- **决议卡片**：
  - 编号（等宽字体）；
  - 标题；
  - 一条进度条，同时显示同意、反对、弃权三段比例；
  - 票数统计，以及发起人、审批方式、截止时间。
- **金额输入**：64px 高，货币符号和数字用大号等宽字体，下方提示"最多两位小数"。
- **申请类型**：用两张可选卡片代替下拉框，每张带一句说明，比如"先借后用，事后核销"。
- **附件**：拖拽上传区加文件列表，列表显示文件名、大小和删除按钮。
- **审批流程预览**：竖向步骤条，分已完成、当前、待处理三种状态，并写明"不可审批本人提交的申请"这条规则。

## 6. 落地到现有代码（选定方案后，作为增量需求走 SDLC）
1. **token 化**：在 `frontend/src/shared/theme.css` 里定义 CSS 变量，并覆盖 Element Plus 变量，让 Element 组件自动换肤：`--el-color-primary`、`--el-border-radius-base`、`--el-bg-color`、`--el-text-color-primary`、`--el-border-color` 等。深色模式用 Element Plus 的 `html.dark` 机制切换。
2. **布局**：重写 `PortalLayout.vue`，桌面端用顶部导航，手机端用底部标签栏，当前页高亮靠 `router-link-active`。`AdminLayout.vue` 沿用同一套 token。管理端以桌面为主，可以更紧凑。
3. **页面**：首页、决议、报销三个页面按原型改；其余页面先只换 token，逐步替换内联样式。
4. **性能**：Element Plus 改为按需引入（unplugin-vue-components），减小目前约 1.6MB 的产物。如果选了 A，在低端设备上关闭 `backdrop-filter`，换成半透明纯色。
5. **小程序**：uni-app 端沿用同一套 token，色值和圆角在 `uni.scss` 里同步。
6. **测试**：现有 vitest 用例不依赖样式，应该不受影响；契约测试照常跑。
