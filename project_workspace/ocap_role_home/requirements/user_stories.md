## 用户故事

### US-354: 游客首页只展示公开内容
- 故事：As a 游客, I want to 先看到社区公开决议、投票与财务公开, so that 我能了解社区再决定是否认证。
- 关联需求：REQ-FUNC-366、371、372、374；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-354-01：Given 已登录但没有任何房屋身份的游客 / When 打开 Web 首页 / Then 依次显示欢迎卡（含“去认证”）、最新公开决议、投票与调查、信息公开、财务公开；不显示“我的房屋”“待我处理”“待办审批”“管理快捷”，且不请求 `/approval/tasks`、`/me/housing`。
- AC-354-02：Given 游客打开首页 / When 查看财务公开 / Then 只显示“账户合计 + 查看报表”，不显示逐账户明细；公开决议条目同时带“业委会/业主代表”来源标签。
- AC-354-03：Given 游客打开小程序首页 / When 浏览首屏 / Then 模块顺序与 Web 一致、单列展示，底部 Tab 仍为“首页/决议/投票/我的”。

### US-355: 同住人使用与产权业主一致的版式
- 故事：As a 同住人, I want to 看到与产权业主相同的首页内容, so that 我能正常参与投票、查看决议与财务公开。
- 关联需求：REQ-FUNC-367、371、372；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-355-01：Given 用户仅以 RESIDENT 身份存在于所有房屋 / When 打开首页 / Then 模块顺序为欢迎卡 → 我的房屋（只读）→ 投票与调查 → 公开决议 → 信息公开 → 财务公开；“我的房屋”不出现邀请同住人、变更户主等管理操作。
- AC-355-02：Given 用户仅以 RESIDENT 身份存在于所有房屋 / When 渲染首页 / Then 不显示“待我处理（同住人申请）”，也不请求 `/me/housing`。
- AC-355-03：Given 同住人打开首页 / When 查看投票、公开决议、财务公开 / Then 内容与产权业主一致，包含业委会决议与业主代表决议两类来源。

### US-356: 产权业主先看房屋与待我处理
- 故事：As a 产权业主, I want to 先看到我的房屋和要我处理的同住人申请, so that 我能及时完成房屋相关决策。
- 关联需求：REQ-FUNC-368、372、374；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-356-01：Given 产权业主有 3 套房 / When 打开首页 / Then 显示“我的房屋 · 3”，可进入房屋明细；模块顺序为欢迎卡 → 我的房屋 → 待我处理 → 投票与调查 → 公开决议 → 财务公开。
- AC-356-02：Given 任一房屋为 HEAD/OWNER 且待审同住人申请数为 2 / When 打开首页 / Then 显示“待我处理 · 2”，点击进入同住人审批；待审数为 0 时整卡不显示。
- AC-356-03：Given 产权业主不是业委会成员 / When 打开首页 / Then 不显示“待办审批”和“管理快捷”，也不请求 `/approval/tasks`。

### US-357: 业主代表优先看到业主达标投票
- 故事：As a 业主代表, I want to 在首页直接看到需要我参与的业主达标投票, so that 我不会漏掉代表表决。
- 关联需求：REQ-FUNC-369、371；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-357-01：Given 业主代表有待参与的业主达标投票 / When 打开首页 / Then 显示“待我表决”卡，逐条显示投票标题、截止时间与参与状态；卡片中不出现财务或决议审批事项。
- AC-357-02：Given 某投票不是业主达标口径（如普通调查）/ When 渲染“待我表决” / Then 该投票不出现在此卡，只出现在“投票与调查”卡。
- AC-357-03：Given 业主代表打开公开决议 / When 查看列表 / Then 同时看到业委会决议与业主代表决议，并以来源标签区分；不显示“待办审批”“管理快捷”。

### US-358: 业委会委员首屏是工作台
- 故事：As a 业委会委员, I want to 先处理审批待办，再查看资金与管理入口, so that 我能高效完成日常事务。
- 关联需求：REQ-FUNC-370、372、373、374；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-358-01：Given 当前有 5 项待我审批 / When 打开首页 / Then 显示“待办审批 · 5”，最多列出 3 条并提供“全部”入口；待办为 0 时不显示列表内容。
- AC-358-02：Given 业委会成员打开首页 / When 查看财务与管理 / Then 财务概览显示账户合计与“报表”入口；管理快捷包含收入表、报销/备用金、历史支出导入三项。
- AC-358-03：Given 业委会成员打开首页 / When 浏览整体 / Then 不再出现 4 张统计卡与 Hero 重复计数徽章；待办、投票、决议的数量只在各自模块标题出现一次。

### US-359: 多重身份按能力组合模块
- 故事：As a 同时拥有多种身份的用户, I want to 一次性看到所有该我处理的事项, so that 我不需要切换身份或页面。
- 关联需求：REQ-FUNC-366、368、369、370；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-359-01：Given 用户既是业委会委员又是某套房户主且有 2 条待审同住人申请 / When 打开首页 / Then 顺序为待办审批 → 待我处理 · 2 → 财务概览 → 管理快捷 → 投票 → 公开决议；“待我处理”只有一张卡。
- AC-359-02：Given 用户既是业主代表又是户主且有 1 条待审申请 / When 打开首页 / Then 顺序为待我表决 → 待我处理 · 1 → 投票 → 公开决议 → 财务公开 → 信息公开，且不重复出现“待我处理”。
- AC-359-03：Given 用户有多套房但待审申请总数为 0 / When 打开首页 / Then 不显示“待我处理”，也不显示数量为 0 的占位卡。

### US-360: 三主题与小程序保持一致
- 故事：As a 用户, I want to 在 Web 三套主题和小程序中看到一致的模块顺序, so that 切换设备或风格时不需要重新适应。
- 关联需求：REQ-FUNC-375；优先级：Should Have；故事点：3 [ESTIMATE]
- AC-360-01：Given 同一角色分别选择霓虹玻璃、极光 Bento、赛博终端 / When 打开首页 / Then 三种主题的模块顺序与栅格占位一致，仅颜色/圆角/动效不同；宽度 ≥768px 时无横向溢出。
- AC-360-02：Given 同一角色在微信小程序打开首页 / When 浏览 / Then 模块顺序与 Web 一致，为单列卡片流，底部 Tab 仍为“首页/决议/投票/我的”，不出现统计卡宫格。
