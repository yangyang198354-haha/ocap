# 用户故事：审批失败终局与重新发起留痕

## 角色 × 功能矩阵

| 角色 | 查看失败单据 | 新建单据再次办理 | 原单重提（仅撤回） | 查看关联留痕 |
|---|---|---|---|---|
| 决议发起人（主任/副主任） | US-277、US-278 | US-277、US-278 | US-277（撤回后） | US-281 |
| 报销/备用金申请人（业委会成员） | US-279 | US-279 | US-279（撤回后） | US-281 |
| 收入表提交人（财务委员） | US-280 | US-280 | US-280（草稿/撤回） | US-281 |
| 其他已登录用户 | US-277（公开决议） | — | — | US-281（仅公开范围内） |

## 用户故事

### US-277: 决议表决失败后原单留痕，只能新建决议
- 故事：As a 决议发起人, I want to 在表决失败后保留原决议并新建一条决议重新表决, so that 失败结果可追溯，且不会误改历史记录
- 关联需求：REQ-FUNC-269、REQ-FUNC-271、REQ-FUNC-272、REQ-FUNC-274；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-277-01：Given 半数同意决议处于审批中 / When 表决截止且同意票未过半 / Then 决议状态为“未通过”，保留同意/反对/弃权数、分母与截止时间，原记录不删除
- AC-277-02：Given 决议已因表决失败结束 / When 发起人打开决议详情 / Then 不出现“修改后重新提交”，并显示“该决议已结束，如需再次表决请新建决议”
- AC-277-03：Given 同上 / When 发起人直接调用原单重提接口 / Then 请求被拒绝，决议状态、内容与投票记录均不变
- AC-277-04：Given 表决失败 / Then 对应审批实例已结束，该决议不再出现在任何人的待办列表中
- AC-277-05：Given 表决失败 / When 发起人新建一条决议（标题可相同） / Then 新决议生成独立记录与新一轮表决，通过后正常生效；新旧两条记录都可查询

### US-278: 指定负责人拒绝的决议同样终局
- 故事：As a 决议发起人, I want to 在指定负责人拒绝后保留原决议并新建一条重新审批, so that 拒绝结果留痕且规则与投票失败一致
- 关联需求：REQ-FUNC-269、REQ-FUNC-272、REQ-FUNC-275；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-278-01：Given 指定负责人审批的决议处于审批中 / When 该负责人点“拒绝” / Then 决议状态为“未通过”，保留拒绝人、拒绝时间与审批意见，原记录不删除
- AC-278-02：Given 决议因拒绝结束 / When 发起人查看详情或尝试原单重提 / Then 不提供原单重提入口且接口拒绝，提示“该决议已结束，如需再次表决请新建决议”
- AC-278-03：Given 拒绝后 / When 发起人新建决议 / Then 新决议独立走指定审批，通过后生效

### US-279: 报销 / 备用金审批失败后原单留痕，只能新建
- 故事：As a 报销或备用金申请人, I want to 在申请被拒后保留原申请并新建一张申请, so that 金额与审批过程可追溯，且不会复用已失败的单据
- 关联需求：REQ-FUNC-269、REQ-FUNC-270、REQ-FUNC-271、REQ-FUNC-272；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-279-01：Given 报销或备用金申请处于审批中 / When 审批人拒绝 / Then 状态为“未通过”，保留原金额、事由、发票与审批记录，原单不删除
- AC-279-02：Given 申请已未通过 / When 申请人查看或直接调用原单重提接口 / Then 不显示重提入口且接口拒绝，提示“该申请已结束，如需再次申请请新建”
- AC-279-03：Given 申请处于审批中 / When 申请人撤回后修改并重新提交 / Then 原单可重提并重新进入审批（保持现有行为）
- AC-279-04：Given 申请人新建一张申请 / Then 新单独立审批，通过后按现有规则计入支出；原失败单状态不变

### US-280: 收入表审批失败后原单留痕，只能新建
- 故事：As a 收入表提交人, I want to 在收入表被拒后保留原表并新建一张收入表, so that 原表金额与审批记录可追溯
- 关联需求：REQ-FUNC-269、REQ-FUNC-270、REQ-FUNC-271、REQ-FUNC-272；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-280-01：Given 收入表处于审批中 / When 审批人拒绝 / Then 状态为“未通过”，保留原表记录与金额，原表不删除
- AC-280-02：Given 收入表已未通过 / When 提交人查看或调用原表重提接口 / Then 不显示“重新提交”且接口拒绝，提示“该收入表已结束，如需再次提交请新建”
- AC-280-03：Given 收入表为草稿或已撤回 / Then 仍可提交或重提（保持现有行为）；已生效只能作废（保持现有行为）
- AC-280-04：Given 提交人新建一张收入表 / Then 新表独立审批，生效后计入收入台账；原失败表状态不变

### US-281: 新旧单据互相关联，失败记录可留痕追溯
- 故事：As a 单据发起人, I want to 在失败单与新单之间看到彼此的关联, so that 我能证明某次失败已经重新发起
- 关联需求：REQ-FUNC-272、REQ-FUNC-273；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-281-01：Given 原单已失败且已新建新单 / When 打开原单详情 / Then 显示“已由 #新单号 重新发起”；打开新单详情时显示“重新发起自 #原单号”
- AC-281-02：Given 已建立关联 / Then 原单的状态、失败原因、票数或拒绝信息保持不变，不被新单覆盖
- AC-281-03：Given 发生失败与新建 / Then 审计日志记录失败原因、操作人与时间，以及新建关联
- AC-281-04：Given 无权限查看原单的用户 / Then 不能通过关联信息看到超出原单可见范围的内容
