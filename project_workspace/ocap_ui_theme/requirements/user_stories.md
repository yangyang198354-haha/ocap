## 用户故事

### US-074: 提供三套界面风格
- 故事：As a 已登录用户（Web 或小程序）, I want to 有 A 霓虹玻璃、B 极光 Bento、C 赛博终端三套界面风格可用, so that 我能按自己喜好使用界面
- 关联需求：REQ-FUNC-069；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-074-01：Given 系统已启用三套风格 / When 用户在 Web 个人中心或小程序"我的"页查看风格选项 / Then 列表恰好包含 3 项，名称依次为"霓虹玻璃""极光 Bento""赛博终端"（名称以最终确认文案为准），每项带可辨识的缩略或色块标识
- AC-074-02：Given 用户选中风格 A 或 C / When 页面渲染完成 / Then 页面为深色底（A、C），选中风格 B 时为浅色底；三套风格的主色、圆角、字体、首页布局与 design_spec §1、§2 对应条目一致
- AC-074-03：Given 用户设备系统为深色或浅色模式 / When 用户打开任一页面 / Then 页面明暗只取决于所选风格，不随系统深浅色改变，且选项中没有"跟随系统"和同一风格的浅/深变体

### US-075: 默认使用风格 B
- 故事：As a 已登录用户（Web 或小程序，含上线前已有账号）, I want to 在没选过风格时看到风格 B, so that 登录后默认就是统一、浅色的极光 Bento 界面
- 关联需求：REQ-FUNC-070；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-075-01：Given 用户账号从未选择过风格（含上线前创建的账号）/ When 该用户首次登录 Web 用户端或小程序 / Then 登录后所有页面呈现风格 B，个人中心的风格选项中"极光 Bento"处于选中状态
- AC-075-02：Given 管理端后台 / When 管理员查看后台全部功能入口 / Then 不存在"设置全站默认风格"的入口，新用户的默认风格恒为 B

### US-076: 在 Web 个人中心选择风格并即时生效
- 故事：As a 已登录用户（Web）, I want to 在个人中心点击某套风格就立刻看到效果, so that 我不用重新登录或刷新就能换风格
- 关联需求：REQ-FUNC-071、REQ-FUNC-073；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-076-01：Given 用户已登录 Web 用户端并打开个人中心（`/me`）/ When 用户点击风格 C / Then 当前页面在 1 秒内整体切换为风格 C，无需刷新或重新登录，且无"确认/预览"步骤；风格选择区块位于现有个人资料等区块之外的独立区块，不新增独立设置页
- AC-076-02：Given 用户当前为风格 C / When 用户再次点击风格 A / Then 页面立即切换为 A，用户可随时来回切换，无次数限制
- AC-076-03：Given 用户点击风格后保存失败（如网络中断）/ When 保存请求未成功 / Then 页面给出可读的失败提示（文案含"保存失败"类说明），选中状态回到保存前的风格，其他个人资料功能不受影响
- AC-076-04：Given 用户处于未登录状态 / When 访问 `/me` / Then 按现有行为跳转登录，不显示风格设置区块（权限行为不变）

### US-077: 在小程序"我的"页选择风格
- 故事：As a 已登录用户（小程序）, I want to 在"我的"页选择三套风格中的任一套, so that 我在手机上也能用自己喜欢的风格
- 关联需求：REQ-FUNC-071、REQ-FUNC-077；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-077-01：Given 用户已登录小程序并打开"我的"页 / When 用户点击风格 A / Then 当前页面与底部标签栏在 1 秒内切换为风格 A，无确认步骤，风格选项为当前系统启用的全部风格
- AC-077-02：Given 用户在 Web 个人中心已选择风格 C / When 用户在小程序登录并打开"我的"页 / Then 小程序呈现风格 C，"我的"页中风格 C 处于选中状态（与 Web 账号级偏好同步）
- AC-077-03：Given 用户在小程序"我的"页选择风格 A / When 用户随后刷新 Web 用户端 / Then Web 用户端呈现风格 A
- AC-077-04：Given 小程序风格保存失败 / When 请求未成功 / Then 页面提示"保存失败"类文案，选中状态回到保存前的风格

### US-078: 风格选择被记住（账号级 + 本设备）
- 故事：As a 已登录用户, I want to 我选的风格下次登录、刷新或换设备都沿用, so that 不必每次重新设置
- 关联需求：REQ-FUNC-072；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-078-01：Given 用户在 Web 选择了风格 C / When 用户刷新页面或退出后重新登录 / Then 登录后所有页面呈现风格 C
- AC-078-02：Given 用户 U 在设备 1 选择风格 C / When U 在设备 2（另一浏览器或小程序）登录 / Then 设备 2 呈现风格 C
- AC-078-03：Given 用户 U1、U2 共用同一浏览器，U1 选了风格 C、U2 从未选择 / When U2 登录 / Then U2 看到风格 B，不受 U1 的选择影响（账号级偏好不串号）
- AC-078-04：Given 前端读取与保存风格偏好所调用的路径、方法、字段 / When 运行前后端契约测试 / Then 每个调用都能对应到后端已有路由与字段，无法对应的调用数 = 0

### US-079: 未登录页面的风格
- 故事：As a 游客/未登录访客, I want to 登录、注册页沿用我在本设备上选过的风格，没选过则是 B, so that 退出登录后界面不会突然变样
- 关联需求：REQ-FUNC-078；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-079-01：Given 本设备没有任何风格记忆 / When 访客打开登录、注册或微信登录回调页（Web），或小程序登录页 / Then 页面呈现风格 B
- AC-079-02：Given 用户此前在本设备选择了风格 C 后退出登录 / When 用户打开登录页 / Then 登录页呈现风格 C
- AC-079-03：Given 访客在登录页 / When 查看页面所有控件 / Then 没有风格切换入口
- AC-079-04：Given 本设备记忆的风格已不在系统启用集合中 / When 访客打开登录页 / Then 登录页呈现风格 B（与 US-086 一致）

### US-080: 新增风格不改业务页面（可扩展）
- 故事：As a 维护者, I want to 新增一套风格只需新增一份风格定义, so that 以后扩展更多风格时不用逐页改动业务代码
- 关联需求：REQ-FUNC-074；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-080-01：Given 在系统中新增一份风格定义（例如名为"测试风格 D"，不改任何业务页面文件）/ When 已登录用户打开 Web 个人中心与小程序"我的"页 / Then 两处风格列表均出现"测试风格 D"，选项总数由 3 变为 4
- AC-080-02：Given 风格列表已出现"测试风格 D" / When 用户选择它 / Then 用户端全部页面（Web 14 页与小程序 11 页）以及未登录页都应用该风格，且没有业务页面文件因此被修改（代码审查的改动文件清单中业务页面数 = 0）
- AC-080-03：Given 新增的风格定义缺少必需内容或不合规 / When 系统加载风格集合 / Then 该风格不出现在列表中，其他风格与页面使用不受影响，并有可定位的错误信息
- AC-080-04：Given 管理端后台 / When 管理员查看全部功能入口 / Then 不存在在运行期新增风格的功能（本期不做，风格定义随发布生效）

### US-081: Web 用户端全部页面应用所选风格
- 故事：As a 已登录用户（Web）, I want to 所有页面都是我选的风格, so that 整个站点观感一致，不是只有首页好看
- 关联需求：REQ-FUNC-075；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-081-01：Given 用户选择了风格 A / When 逐一访问用户端 14 个页面（登录、注册、微信回调、首页、个人中心、我的房屋、决议列表/详情、待办、报销/备用金、收入表、投票/调查列表/详情、财务报表）及布局/导航 / Then 每个页面的背景、文字、按钮、表单、表格、状态标签均呈现风格 A，无残留的旧版样式（逐页检查清单 14/14 通过）
- AC-081-02：Given 用户选择了风格 C / When 同样访问 14 个页面 / Then 逐页检查均呈现风格 C，14/14 通过；风格 B 同理 14/14 通过
- AC-081-03：Given 任一页面在三套风格下 / When 对比切换前后同一页面的业务内容 / Then 业务数据、按钮功能、权限控制与切换前一致（只变外观，不变内容）

### US-082: 管理端固定使用风格 B
- 故事：As a 管理员, I want to 管理后台是统一的风格 B 且不受普通用户设置影响, so that 后台界面稳定一致
- 关联需求：REQ-FUNC-076；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-082-01：Given 管理员登录管理端 / When 访问管理员登录页及 8 个后台页（业主清册、申诉、房屋关系、业委会席位、审批流程、财务、账号、审计/配置）与布局 / Then 9 个页面均呈现风格 B（9/9 通过）
- AC-082-02：Given 同一浏览器中某普通用户已选择风格 C / When 管理员在该浏览器访问管理端 / Then 管理端仍呈现风格 B，普通用户的选择不影响管理端
- AC-082-03：Given 管理端任一页面 / When 查看全部控件 / Then 不存在风格切换或风格设置入口；管理员账号没有个人中心页的现状不变
- AC-082-04：Given 管理员登录态与普通用户登录态相互独立 / When 管理员访问管理端 / Then 管理端的登录、权限和令牌行为与改动前一致

### US-083: 小程序全部页面应用所选风格
- 故事：As a 已登录用户（小程序）, I want to 小程序所有页面和底部标签栏都使用我选的风格, so that 手机上也是统一观感
- 关联需求：REQ-FUNC-077；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-083-01：Given 用户选择了风格 A / When 逐一访问小程序 11 个页面（首页、登录、完善资料、我的房屋、决议列表/详情、投票列表/详情、报销/备用金、我的、手机号）及底部标签栏 / Then 每个页面与标签栏均呈现风格 A（11/11 通过）；风格 B、C 同理
- AC-083-02：Given 小程序底部标签栏 / When 查看标签项 / Then 保持现有 4 项（首页、决议、投票、我的），报销/备用金入口位置不变（是否增加"报销"为待定问题 Q125，当前按保持现状验收）
- AC-083-03：Given 用户未登录小程序且本设备无记忆 / When 打开小程序登录页 / Then 呈现风格 B；本设备有记忆时呈现记忆的风格
- AC-083-04：Given 小程序任一页面在三套风格下 / When 对比切换前后业务内容 / Then 业务数据与功能与切换前一致

### US-084: 手机窄屏适配（底部标签栏与吸底提交）
- 故事：As a 已登录用户（Web，手机浏览器）, I want to 窄屏下有底部标签栏且表单提交按钮固定在底部, so that 单手也能方便操作
- 关联需求：REQ-FUNC-079；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-084-01：Given 用户在窄屏（手机）打开 Web 用户端登录后页面 / When 页面渲染完成 / Then 顶部导航隐藏，底部出现标签栏，恰好 5 项，依次为"首页""决议""投票""报销""我的"，各项配文字标签；点击各项分别进入首页、决议列表、投票/调查列表、报销/备用金、个人中心
- AC-084-02：Given 用户在窄屏打开报销/备用金等表单页 / When 页面渲染完成并滚动内容 / Then 提交按钮始终吸附在底部标签栏上方，不被标签栏遮挡，页面内容底部留有不被遮挡的空间
- AC-084-03：Given 用户在宽屏（桌面）打开同一页面 / When 页面渲染完成 / Then 显示顶部导航，不显示底部标签栏，提交按钮不吸底（桌面布局不变）
- AC-084-04：Given 用户在窄屏 / When 查看三套风格下的页面 / Then 页面为单列布局，8 个导航项不再挤成多行，三套风格均适用

### US-085: 导航高亮当前页面
- 故事：As a 已登录用户（Web）, I want to 导航里能看出我当前在哪个页面, so that 不容易迷路
- 关联需求：REQ-FUNC-080；优先级：Should Have；故事点：2 [ESTIMATE]
- AC-085-01：Given 用户在 Web 用户端决议列表页 / When 查看顶部导航（宽屏）或底部标签栏（窄屏）/ Then 仅"决议"项处于高亮状态，其余项无高亮；在决议详情页"决议"项同样高亮
- AC-085-02：Given 用户切换到投票页 / When 页面跳转完成 / Then 高亮项由"决议"变为"投票"，任一时刻高亮项数量 = 1

### US-086: 已保存风格被下线时回退到 B
- 故事：As a 已登录用户, I want to 我选的风格万一被下线时系统自动回到默认风格且我能重新选, so that 不会因此打不开页面
- 关联需求：REQ-FUNC-081；优先级：Should Have；故事点：3 [ESTIMATE]
- AC-086-01：Given 用户已保存风格 D，且风格 D 随后从启用集合中移除 / When 用户登录或刷新页面 / Then 页面呈现风格 B，业务功能可正常使用，不出现白屏或报错
- AC-086-02：Given 用户处于回退后的风格 B / When 用户打开个人中心或小程序"我的"页 / Then 风格列表中不含已下线的风格，用户可重新选择任一启用风格并立即生效
- AC-086-03：Given 本设备（未登录）记忆的风格已下线 / When 访客打开登录页 / Then 呈现风格 B

### US-087: 状态不只靠颜色表达，关键组件按规范
- 故事：As a 已登录用户（Web/小程序）, I want to 状态标签有圆点和文字、关键组件样式统一, so that 色觉不敏感时也能读懂状态
- 关联需求：REQ-FUNC-082；优先级：Should Have；故事点：3 [ESTIMATE]
- AC-087-01：Given 决议列表中有表决中、已通过、未通过三种决议 / When 用户在任一风格下查看 / Then 三种状态标签均为"圆点 + 文字 + 底色或描边"，分别对应警示、成功、危险语义；将页面转为灰度后三者仍可凭文字与圆点区分
- AC-087-02：Given 用户打开报销/备用金申请页 / When 查看金额输入、申请类型选择、附件区、审批流程预览 / Then 这 5 类组件（含决议卡片）在三套风格下均按 design_spec §4 呈现
- AC-087-03：Given 小程序决议页 / When 用户查看状态标签 / Then 与 Web 一致采用"圆点 + 文字 + 底色或描边"

### US-088: 可访问性（对比度、点击区域、焦点、图标文字）
- 故事：As a 已登录用户或访客, I want to 文字清晰、按钮够大、键盘能看到焦点, so that 各种使用条件下都能顺利操作
- 关联需求：REQ-NFUNC-005、REQ-NFUNC-006；优先级：Should Have；故事点：5 [ESTIMATE]
