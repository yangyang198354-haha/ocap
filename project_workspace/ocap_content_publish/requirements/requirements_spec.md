# 需求规格说明书 — ocap 信息公开发布与多平台内容中心（PHASE_01）

## 执行摘要

- 业务背景：用户原文 `"管理员在web 后端可以发布信息公开。可以向微信公众号web 版一样在前端辫子文字，能够设计段落，对其，颜色。超链接。要求和微信公众号编辑页面功能等价。"`、`"在web 上发布后，可以一键保存到公众号，小红书，头条账户的草稿箱里。这些账户需要提前保存账户信息和认证信息。"`、`"让管理员可以工作这些功能编辑图文，视频资料，并且通过大语言模型和提示词生成文案。一键发布到多个平台。"`。原文笔误按以下理解处理（均为理解，不改写原文引用）：「辫子文字」= 编辑文字；「蔬菜库」= 素材库；「gentplatform / genplatform」= 用户的 GenPlatform 项目；「工作这些功能」≈ 使用这些功能；「才分用户故事」= 再拆分用户故事（流程要求，见 C-25）。
- 本版（0.3.0）在 0.2.0 基础上落实用户 2026-11-10 的第二次答复：用户原话 `"Q19=A，其他按推荐，需求确认，拆用户故事"`（PM 映射：Q-CP-19=A、Q-CP-20=A、Q-CP-14=A、OQ-5 确认），并表示需求确认、放行用户故事拆分。0.2.0 依据的第一次答复原话为 `"Q4=B; Q5=B，其他都按推荐"`。逐题答复见"已答复问题"。
- 统计：功能需求 24 条（REQ-FUNC-099 ~ 122，本版无新增条目）/ 非功能需求 3 条（REQ-NFUNC-016 ~ 018）。编号续接既有最大号（REQ-FUNC-098、REQ-NFUNC-015，来自 ocap_registry_import）。
- INFERRED：0 条，0 ÷ (24 + 3) = 0/27 = 0.0%，低于上限 20%。0.1.0 中的 4 条推断项（I-1 ~ I-4）已由用户在本版答复中确认接受（OQ-5 关闭），记为 [U]。
- 优先级规则：用户未给优先级信号，用户明确提到的功能为 Must Have，其余为 Should Have。按此规则：Must Have 21 条（功能 21），Should Have 6 条（功能 3 + 非功能 3）。REQ-FUNC-120 ~ 122 因用户明确选择（Q-CP-04=B、Q-CP-05=B）列为 Must Have。
- 剩余开放问题（均非阻断）：
  - Q-CP-14 余项：素材库总配额用户未给数值，不自拟（C-29）；另 OQ-6（视频格式清单在 C-18 中没有对应口径）。
  - OQ-1（画像 P11-3 须补录，进入 GROUP_B 前）、OQ-2（非功能数值与默认值）、OQ-3（信息公开与决议公开的关系）。
  - 阻断性问题：无（Q-CP-19、Q-CP-20 已答复）。
- 外部 API 事实：微信公众号、小红书、今日头条、火山方舟、DeepSeek、视频生成服务、文生图服务的接口能力、字段、限制均 [UNSOURCED]，本文不作为需求事实断言。
