## 用户故事

### US-183: 逐级选房四级选项按数字自然顺序排列
- 故事：As a 登录用户, I want to 在"我的房屋"选择房屋时，楼栋、单元、楼层、户号都按数字顺序排列, so that 我能按直觉快速找到自己的房屋（"楼栋，单元，楼层，户号的排序方式必须统一"）
- 关联需求：REQ-FUNC-173、REQ-FUNC-174；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-183-01：Given 清册有楼栋 "1"、"2"、"10"、"11" / When 用户打开"选择房屋"的第一级 / Then 楼栋选项依次为 1、2、10、11（不是 1、10、11、2）
- AC-183-02：Given 某楼栋下单元为 "1"、"2"、"10"，户号为 "101"、"902"、"1001" / When 用户逐级选择到单元与户号 / Then 单元依次为 1、2、10，户号依次为 101、902、1001
- AC-183-03：Given 某单元下楼层为 "-1"、"1"、"2"、"10" / When 用户选择楼层 / Then 依次为 -1、1、2、10（负层在前，与变更前楼层行为一致，不退化）
- AC-183-04（Q-SF-03=A）：Given 选项值含非数字文字，如户号 "A2"、"A10"、"5" / When 用户选择户号 / Then 纯数字 "5" 在前，其后依次为 "A2"、"A10"（数字段按数值比较），页面无报错，选项无丢失、无重复
- AC-183-05：Given 某一级所有值都为空（如车位无单元） / When 用户逐级选择 / Then 该级被跳过，不出现空选项，其余各级顺序规则不变
- AC-183-06（Q-SF-04=A）：Given 某层级的楼层值为 "负二"、"负一"、"1"、"2"、"-1" 中的若干个 / When 用户选择楼层 / Then 负二 排在 负一 之前，负一 与 -1 视为同一数值（-1）、二者都排在 1、2 之前；所有值均出现，无丢失

### US-184: Web 与小程序选房顺序一致
- 故事：As a 登录用户, I want to 在 Web 门户和微信小程序里看到相同的选房顺序, so that 换端使用时不用重新适应
- 关联需求：REQ-FUNC-175；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-184-01：Given 同一份清册数据 / When 分别在 Web 用户端与小程序逐级选择房屋 / Then 四级中每一级的选项顺序逐项相同
- AC-184-02：Given 清册新增楼栋 "3" / When 两端分别刷新选择页 / Then 两端都把 "3" 排在 "2" 之后、"10" 之前
- AC-184-03（Q-SF-05=A、Q-SF-11=A）：Given 清册含楼栋 "1"、"10" 与"地下车位" / When 两端分别打开第一级 / Then 两端顺序均为 1、10、地下车位（地下车位在最后），逐项相同

### US-185: 在楼栋级直接选择"地下车位"
- 故事：As a 登录用户, I want to 在选楼栋的地方直接选到"地下车位", so that 我不用进入 1 栋再翻找负层车位（"选择车位体验很差。应该在选楼栋的地方选择地下车位"）
- 关联需求：REQ-FUNC-176；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-185-01（Q-SF-02=A、Q-SF-11=A）：Given 清册中存在楼栋为"地下车位"的车位 / When 用户打开"选择房屋"第一级 / Then 选项中出现文字"地下车位"，且排在所有编号楼栋之后
- AC-185-02：Given 车位已改归属"地下车位" / When 用户选择"1"栋并继续逐级选择 / Then 楼层与户号选项中不再出现原负一、负二层的车位
- AC-185-03：Given 清册中没有任何楼栋为"地下车位"的记录 / When 用户打开第一级 / Then 不出现"地下车位"选项，其余楼栋选项不受影响

### US-186: 选"地下车位"后再选负层与车位号
- 故事：As a 登录用户, I want to 选"地下车位"后继续选负一层或负二层，再选车位号, so that 我能完成车位的认证（"再选负一、负二层"）
- 关联需求：REQ-FUNC-177；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-186-01：Given 用户已选"地下车位"，地下车位有负一层、负二层车位 / When 用户进入下一级 / Then 单元级被跳过，楼层选项依次为负二、负一（数值升序，负层在前，两层均出现且无重复，Q-SF-04=A），选定楼层后车位号选项显示该层全部车位，类型为"车位"
- AC-186-02：Given 用户选定一个地下车位并提交认证 / When 该用户手机号在清册该车位名下 / Then 认证结果与现有逐级选择认证一致（成功后该车位出现在其已认证房屋中；手机号不在清册则给出与现有一致的"未登记"类提示）
- AC-186-03：Given 用户选择"地下车位"后返回修改第一级为 "2" / When 用户查看下一级 / Then 下一级选项按 2 栋的单元/楼层重新加载，不残留地下车位的楼层或车位号

### US-187: 从测试环境清册导出并生成地下车位已改正的导入文件
- 故事：As a 管理员, I want to 得到一份从现有清册只读导出、按导入模板格式生成、且负一/负二层车位已归属"地下车位"的新导入文件, so that 它能被现有批量导入通过预检，并与现有数据一致（"把这个导入文件改对"；原文件服务器上不存在，用户答复 Q-SF-01=B）
- 关联需求：REQ-FUNC-178、REQ-NFUNC-032、C-51、C-55、C-56；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-187-01（Q-SF-01=B、Q-SF-07=A）：Given 用户已另行授权在测试机只读导出 / When 导出并生成导入文件 / Then 文件表头与现有导入模板一致（楼栋、单元、楼层、户号、专有部分类型、专有部分面积（平方米）、业主姓名、手机号）；类型为车位且楼层为负层（负一/负二，与 -1/负1 等价）的每一行楼栋均为"地下车位"；其余行逐单元格与清册现有数据相同；被改动的行数等于按此规则识别出的记录数
- AC-187-02：Given 同一时点的清册 / When 对比导出文件与数据库 / Then 导出文件的专有部分记录数、业主数、手机号数（去重）与数据库对应计数逐项相等（差 0）；导出前后数据库记录数、业主数不变（只读，C-56）
- AC-187-03：Given 生成的导入文件 / When 通过现有批量导入功能做预检 / Then 整个文件未被拒绝，失败行数为 0，预检期间清册未发生任何改变（基线 AC-100-01）
- AC-187-04：Given 文件中楼层、户号、手机号为 "0801"、"13800000000" 这类带前导零或长数字的值 / When 生成文件并再次预检 / Then 这些单元格仍为 "0801"、"13800000000"，无前导零丢失、无科学计数或 "3.0" 改写（基线 AC-093-04）
- AC-187-05：Given 数据库修正（REQ-FUNC-179）已执行 / When 用该文件预检 / Then 新增专有部分数为 0、新增业主数为 0；Given 数据库修正尚未执行，则交付说明明确写出"此时导入会在'地下车位'下新增这些车位，与原挂在 1 栋下的记录并存，须先执行数据库修正或另行决定顺序"
- AC-187-06（C-55）：Given 生成的导入文件含姓名与手机号 / When 检查代码仓库（含 project_workspace 文档与测试数据）与报告、日志 / Then 仓库内检索不到该文件，也检索不到其中的姓名或手机号；报告与日志只出现计数
- AC-187-07：Given 用户未授权导出 / When 开发与验收进行 / Then 不连接测试机、不生成含真实数据的文件；验收只用合成样例，并在交付说明中写明"真实文件未生成，等待授权"
- AC-187-08：Given 导出过程中读取失败或中断 / When 失败发生 / Then 不产生残缺文件被误当作完整文件使用（失败时给出明确失败信息，已生成的部分文件被标记或清除），测试环境数据库无任何写入

### US-188: 测试环境数据库同步修正且不破坏绑定
- 故事：As a 管理员, I want to 把测试环境数据库里已导入的负一、负二层车位同步改归属"地下车位", so that 数据与导入文件一致（"同时数据库里面的数据也修改正确"）
- 关联需求：REQ-FUNC-179、REQ-NFUNC-032、C-51、C-52；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-188-01（Q-SF-07=A、Q-SF-08=A）：Given 用户已另行明确授权在测试环境执行数据修正 / When 修正完成 / Then 专有部分记录总数与修正前相等；已认证业主绑定数（含车位）与修正前相等；被识别记录（类型为车位且楼层为负层）的楼栋均为"地下车位"；其余记录改动数为 0
- AC-188-02：Given 某车位已有已认证业主 / When 修正完成 / Then 该业主在"我的房屋"中仍绑定同一车位（记录标识不变），名称显示为修正后的名称，认证状态与角色不变
- AC-188-03（Q-SF-08=A）：Given 修正会使某记录的专有部分标识与既有记录重复 / When 执行修正 / Then 该记录不被修改，整批停止并列出冲突记录清单，数据库保持修正前状态（记录总数、各记录内容与修正前一致）
- AC-188-04：Given 修正已执行一次 / When 再次执行同样的修正 / Then 新增记录数为 0，被改动记录数为 0
- AC-188-05：Given 用户未另行授权 / When 开发完成 / Then 不对测试环境数据库做任何写入
- AC-188-06（NFUNC-032）：Given 授权执行修正 / When 修正前 / Then 已生成可还原的备份；Given 之后按备份还原 / Then 还原后与修正前逐记录一致（差异 0）

### US-189: 后台清册多个过滤器
- 故事：As a 管理员, I want to 在后台"业主清册"页按楼栋、单元、户号、类型、产权业主姓名、产权业主电话过滤, so that 我能快速定位专有部分和业主（"应当设置多个过滤器"）
- 关联需求：REQ-FUNC-180、REQ-FUNC-182、REQ-NFUNC-033；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-189-01（Q-SF-09=A）：Given 清册有楼栋 "1" 与 "10" 的记录 / When 管理员把楼栋过滤设为 "1" / Then 列表只含楼栋为 "1" 的记录，楼栋 "10" 的记录不出现（精确匹配），分页总数等于符合条数
- AC-189-02：Given 清册中有 单元为 "2"、户号为 "902" 的记录 / When 管理员设置单元 "2" 与户号 "902" / Then 仅返回同时满足两者的记录
- AC-189-03：Given 某专有部分类型为车位 / When 管理员设置类型为"车位" / Then 列表只含车位；选择"未登记类型"时只含未登记类型的记录
- AC-189-04（Q-SF-09=A）：Given 业主姓名为"张三丰" / When 管理员在姓名过滤输入"张三" / Then 该专有部分出现在结果中（包含匹配）；输入"李四"时不出现
- AC-189-05（Q-SF-09=A）：Given 业主手机号为 13800001234 / When 管理员在电话过滤输入"1234" / Then 该专有部分出现在结果中，且结果中显示完整手机号；输入"9999"时不出现
- AC-189-06：Given 管理员设置了楼栋"1"与类型"车位"且没有记录同时满足 / When 查询 / Then 列表为空，显示空状态，总数为 0，页面无报错
- AC-189-07：Given 非管理员账号 / When 访问业主清册列表或带过滤条件访问 / Then 被拒绝，不返回任何清册数据（REQ-NFUNC-033）
- AC-189-08：Given 管理员清空全部过滤条件 / When 重新查询 / Then 列表恢复为全部记录，总数与过滤前相同
- AC-189-09（Q-SF-10=B）：Given 管理员打开业主清册页 / When 查看过滤器区域 / Then 过滤器恰为 楼栋、单元、户号、类型、产权业主姓名、产权业主电话 六项加原有标识搜索，不出现"楼层"过滤

### US-191: 过滤器界面全部使用中文
- 故事：As a 管理员, I want to 过滤器的标签、占位文字和选项都是中文, so that 页面没有英文"select"（"现在的按类型筛选下拉框里面写的是 select，新增、调整的过滤器应当用中文"）
- 关联需求：REQ-FUNC-183；优先级：Must Have；故事点：2 [ESTIMATE]
- AC-191-01：Given 管理员打开业主清册页且未选任何过滤条件 / When 查看类型下拉与其他新增过滤器 / Then 页面上这些控件的可见文字不含英文 "select"（含大小写），均为中文占位或标签（如"全部类型"、"楼栋"、"单元"、"户号"、"产权业主姓名"、"产权业主电话"）
- AC-191-02：Given 管理员展开类型下拉 / When 查看选项 / Then 选项依次为 全部类型、未登记类型、住宅、公寓、商铺、车位、其他，无英文
- AC-191-03：Given 过滤结果为空 / When 查看表格 / Then 空状态文字为中文，不显示英文 "No Data"

### US-192: 已认证房屋列表按数字自然顺序排序且两处一致
- 故事：As a 登录用户（已认证业主或同住人）, I want to 主页和"我的房屋"里我的已认证房屋按同一数字自然顺序排列, so that 两处看到的顺序一致、不再一处按标识文本、一处按认证时间（用户答复 Q-SF-06=A；关闭 ocap_product_review DEF-A 的排序部分）
- 关联需求：REQ-FUNC-184、REQ-FUNC-173、REQ-FUNC-174；基线 AC-157-01；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-192-01：Given 用户 U 已认证房屋 2栋、10栋、"地下车位"下的车位，且认证时间的先后顺序与上述顺序相反 / When U 分别查看主页的已认证房屋列表（个人身份数据）与"我的房屋"列表 / Then 两处的房屋顺序都是 2栋、10栋、地下车位车位（逐项相同），不是文本顺序（10栋 在 2栋 之前）也不是认证时间顺序
- AC-192-02：Given 同上用户，Web 与小程序两端 / When 两端分别打开个人中心/"我的"页与"我的房屋" / Then 四处列表的房屋顺序逐项相同；重复刷新 5 次，顺序与汇总身份均不变（基线 AC-157-01）
- AC-192-03：Given 用户 U 在房屋 A 为户主、在房屋 B 为同住人，且 A 按自然顺序排在 B 之前 / When U 查看 / Then 仍列出两行：A（户主）、B（同住人），汇总身份显示不变（基线 AC-157-01/02 不退化），仅顺序按本需求规则
- AC-192-04：Given 游客（没有任何认证房屋） / When 查看主页与"我的房屋" / Then 两处均显示"暂无已认证房屋"（基线 AC-157-03），无报错
